Static types are now hidden unless they opt in with `Annotation.UserType.set()`; types persisted in a space are always shown. `UserType` takes optional `tags` that surfaces filter on: `Annotation.UserType.set({ tags: [Collection.ItemTag] })` puts a type in a collection's create dialog. Check visibility with `TypeOptions.isUserType` / `TypeOptions.isUserObject`, and tags with `TypeOptions.hasUserTypeTag`. A collection takes any object of a user-facing type; `ContainerModel.link` and `ContainerModel.add` throw on anything else (check first with `ContainerModel.canAdd`), and `SpaceOperation.AddObject` fails with a `SpaceOperationError` before writing anything. Objects without the collection tag join through the new Add to collection action (`CollectionOperation.OpenAddToCollection`) on nav tree items and cards, which opens a searchable list of the space's collections. Where a new object goes when no target is given is an `AppCapabilities.DefaultParent` rule keyed by tag: `DefaultParent.add` files an object under its target or its default parent, and `SpaceOperation.AddObject` consults the rules too, so it now declares `Capability.Service`. plugin-space contributes the rule that files `Collection.ItemTag` types into the space's root collection, creating it when a space has none. Breaking: `Annotation.HiddenAnnotation` and `CollectionItemAnnotation` are removed. Drop `HiddenAnnotation.set(true)`, replace `CollectionItemAnnotation.set(true)` with `Annotation.UserType.set({ tags: [Collection.ItemTag] })`, and add `Annotation.UserType.set()` to any other type users should see.
