Fix `waitUntilHeadsReplicated` hanging when the awaited change merges without visible patches (a concurrent write into an already-conflicted key) by waiting on `heads-changed` instead of `change`, and make `TestReplicationNetwork` register connections so removing a replicator tears down its local end, enabling transport-level partition/heal in tests. Move the `Lens` object-lens namespace from `@dxos/echo-panproto` into `@dxos/echo`, beside `Type`/`Obj`/`Annotation`; `@dxos/echo-panproto` keeps the `Panproto` wire lens, its runner, and the `useLens` React hooks. Fix `db.runMigrations` clobbering concurrent edits and silently dropping retired properties: an object migration now writes only its changed data keys, the type, and a migration marker in one automerge change, so fields the migration doesn't touch — including a peer's concurrent edit to one — survive. Add `Migration.fromLens`, which derives an object migration from a `Lens`: the lens's coverage report catches an unreviewed dropped or suspicious mapping at definition time, and `Lens.checkLaws` guards every object against a lossy conversion before its transform output is written. Add `ObjectCore.foldAt` (internal), which writes a fold-forward value concurrent with everything since a recorded heads so it lands as a real Automerge conflict instead of clobbering a later direct edit, and `Obj.getConflict`, which reads that conflict back with a user-wins policy resolved from each alternative's change message. Fix `ConvergenceKeyMerger` dropping an edit made on a losing fan-out duplicate before its merge: the winner's flat per-field merge trivially "defined" every field a migration wrote on both copies, so `#mergeCandidates` now also replays each loser's edits since its own creation heads onto the winner at the winner's creation heads — an unconflicted edit lands cleanly, a field both copies edited becomes a real Automerge conflict, and text fields replay character-wise when (and only when) both copies' creation-time text agrees.
