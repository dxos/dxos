Fix `waitUntilHeadsReplicated` hanging when the awaited change merges without visible patches (a concurrent write into an already-conflicted key) by waiting on `heads-changed` instead of `change`, and make `TestReplicationNetwork` register connections so removing a replicator tears down its local end, enabling transport-level partition/heal in tests. Move the `Lens` object-lens namespace from `@dxos/echo-panproto` into `@dxos/echo`, beside `Type`/`Obj`/`Annotation`; `@dxos/echo-panproto` keeps the `Panproto` wire lens, its runner, and the `useLens` React hooks. Fix `db.runMigrations` clobbering concurrent edits and silently dropping retired properties: an object migration now writes only its changed data keys, the type, and a migration marker in one automerge change, so fields the migration doesn't touch — including a peer's concurrent edit to one — survive. Add `Migration.fromLens`, which derives an object migration from a `Lens`: the lens's coverage report catches an unreviewed dropped or suspicious mapping at definition time, and `Lens.checkLaws` guards every object against a lossy conversion before its transform output is written. Add `ObjectCore.foldAt` (internal), which writes a fold-forward value concurrent with everything since a recorded heads so it lands as a real Automerge conflict instead of clobbering a later direct edit, and `Obj.getConflict`, which reads that conflict back with a user-wins policy resolved from each alternative's change message. Fix `ConvergenceKeyMerger` dropping an edit made on a losing fan-out duplicate before its merge: the winner's flat per-field merge trivially "defined" every field a migration wrote on both copies, so `#mergeCandidates` now also replays each loser's edits since its own creation heads onto the winner at the winner's creation heads — an unconflicted edit lands cleanly, a field both copies edited becomes a real Automerge conflict, and text fields replay character-wise when (and only when) both copies' creation-time text agrees. Fix a nested record or array element keeping a stale `id` field after a remote change removed it (e.g. an element reused by a concurrent reorder). Add `db.foldForward` (run after `runMigrations` and on replicated updates), which carries a late write to a migrated object's retired properties forward into the new shape — character-wise for renamed text — as a history-native conflict when the new property was also edited. Add `Lens.compose`, `Lens.invert` (renames, automatic matches and named codecs), and version-aware `Lens.findPath`/`Lens.resolveView`, which view an object through the shortest chain of registered lenses between type versions with a deterministic tie-break. Add multi-object migrations: `ensure`/`assign` on the migration context (create-or-find by convergence key; value-compared cross-object writes), `Migration.defineFanIn` (declared collision and removal), `Migration.defineStampElementIds` and `Migration.defineArrayFanOut` (stable element ids, conflict-gated split), and `Migration.findOrphanedChildren` for reviewing duplicates. Fold-forward also carries a late write to a lens overlay (from a client still viewing through the lens) into the property a `fromLens` migration promoted it to. Fold-forward writes now use a deterministic fold actor per peer, document, object and migration step (bounded actor growth, no clobbering across scopes), and the migration marker records every step so chained migrations fold a late write through each step in order. Fan-in now switches an absorbed child's type in the same change as its tombstone, and fold-forward carries a late edit to an absorbed child into the parent — past the declared collision policy only for keys the parent originally took from that child. Array fan-out now splits in one change with a per-property marker, and fold-forward carries late source-array edits into their children (new id'd elements become children, removed ones are left for `findOrphanedChildren`, duplicate refs collapse); the migration context's `ensure` is now async and finds children created by earlier runs. Fold-forward now passes real `Ref`s to transforms and writes them back intact, folds only the keys a late write changed, orders a fold after every earlier fold in its scope (including across a reload), finds fan-in children whose type `to` switched, and checkpoints the heads a pass read; `runMigrations` and `foldForward` are serialized per database.
