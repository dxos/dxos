The MCP server projects a fixed three-tool surface — `queryOperations`, `invokeOperation` and `loadSkill` — instead of one tool per operation, so the advertised tool surface stays fixed however many operations a host registers (an unfiltered `queryOperations` response still grows with the registry, but it is fetched on demand rather than loaded into every session), and the surface is backed directly by ECHO's `Registry` holding `PersistentOperation` and `Skill` entities. **Breaking:** operations are no longer advertised as MCP tools — a client calls `queryOperations` to search them (text queries evaluate through the registry's `Filter.text`; a `keys` lookup returns input/output JSON Schemas) and `invokeOperation` to run one — and the `McpRegistry` namespace is removed: hosts now provide echo's `Registry.Service` plus the new `McpServer.Host` (invoke seam and session spaces), with `McpServer.hydrateRegistry` building a registry from wire records for RPC-backed hosts. `loadSkill` lists every skill when called with no argument, and per-operation safety hints moved from tool annotations to the `mutation` field of a `queryOperations` row.
