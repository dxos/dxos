The MCP server projects a fixed three-tool surface — `findOperations`, `invokeOperation` and `skillLoad` — instead of one tool per operation, so a client's context no longer grows with the size of the operation registry, and the surface is backed directly by ECHO's `Registry` holding `PersistentOperation` and `Skill` entities. **Breaking:** operations are no longer advertised as MCP tools — a client calls `findOperations` to search them (text queries evaluate through the registry's `Filter.text`; a `keys` lookup returns input/output JSON Schemas) and `invokeOperation` to run one — and the `McpRegistry` namespace is removed: hosts now provide echo's `Registry.Service` plus the new `McpServer.Host` (invoke seam and session spaces), with `McpServer.hydrateRegistry` building a registry from wire records for RPC-backed hosts. `skillLoad` lists every skill when called with no argument, and per-operation safety hints moved from tool annotations to the `mutation` field of a `findOperations` row.
