# multiple-changesets: the WebSocketMuxer send hang is unrelated to the reopened-space sync-state fix on this branch
'@dxos/edge-client': patch
---

`WebSocketMuxer.send` writes a segmented (16 KiB or larger) message in one run of its send task, a `DeferredTask`, and resolves right after its last segment. The task waits only while the socket is connecting or has over 1 MB buffered; before, every segment waited for its own timer turn. `destroy()` disposes the task's context, so no timer outlives the muxer, and any later send rejects. While a message waits, a later message from the same service waits behind it instead of overtaking it. `send` now rejects instead of hanging or dropping the message: with `WebSocketClosedError` on a closing or closed socket, or when the socket starts closing or the muxer is destroyed while the message waits; with the new `MessageTooLargeError` past Cloudflare's limit (1 MB sent whole, 32 MB segmented), where it used to log and drop; or with the error the socket's `send` threw. A throwing socket no longer stalls every later segmented send on that muxer. Once a message is cut off mid-sequence, later segmented sends on that muxer reject, because the receiver still holds its first segments. Past 255 services, channels are shared instead of wrapping onto a channel id already in use.

The new `sendSync` writes every frame before it returns, with no queue, timer or back-pressure. It is for servers only, such as the EDGE router on workerd, since it holds the thread until the whole message is written; clients keep using `send`. It throws where `send` rejects, and throws instead of writing while `send` has messages queued.

`EdgeWsConnection` no longer restarts a connection after heavy local work blocked its event loop for most of the 12 s keepalive window; the restart cost a re-handshake and failed the in-flight sync rounds. A stalled loop is excused only until three probes in a row go unanswered, so a dead socket is still restarted during long stretches of heavy work.
