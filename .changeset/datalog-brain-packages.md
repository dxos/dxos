---
'@dxos/datalog': minor
---

Add `@dxos/datalog`, a dependency-free Datalog engine (parser, static checks, incremental stratified semi-naive evaluation with provenance, aggregates and pluggable built-ins) that runs in the browser, workerd and Node, and `@dxos/brain`, which encodes pipeline-rdf `RDF.Fact`s directly as Datalog relations and evaluates compiled goal rules: canonical-vocabulary shorthand, the `about` / `concerns` / time built-ins, and wakes on new bindings, first achievement and sub-goal status changes. `@dxos/pipeline-rdf` now preserves a fact's illocution (force, mood, addressee) through the fact store, and exports its RDF vocabulary, fact ↔ triples mapping and predicate normalizer as `RDF.Vocab`, `RDF.Mapping` and `RDF.Predicate`, which `@dxos/brain` uses to canonicalize predicates.

**Breaking (`@dxos/pipeline-rdf`):** `RDF.Term` is now a discriminated union tagged by `kind` — `{ kind: 'entity', entity, label? }` or `{ kind: 'literal', literal }` — so ECHO can store facts as they are. Code that builds terms must add `kind`, and code that narrows with `'entity' in term` should switch on `term.kind`; `RDF.termValue` returns a term's join key. The RDF triple form is unchanged, so facts already in a `FactStore` read back with the tag. `RDF.Fact` gains an optional `pass` (extraction pass id, serialized as `sx:pass`). plugin-agent's `FactEntry` (`0.2.0`) now holds one `RDF.Fact` unchanged per feed item, keyed by the fact's id, and a new `ExtractionPass` item closes each extraction pass (its id is each fact's `pass`); the `ReadSource` operation returns `pass` in place of `entry`. Entries written as `0.1.0` are no longer read, so chats are re-read from the start.
