`@dxos/agent-runtime` adds `CodeMode`, a `TurnProducer` that runs an agent's turns in "code mode": the model carries exactly one tool, `eval`, and reaches the workspace by writing code rather than by calling a tool per action. Operations bound by the conversation's skills are not projected as tools at all — each is a function the code calls — so a task spanning several of them costs one turn instead of one turn each. Only what the code prints goes back into the model's context — or, when a program prints nothing at all, the value it produced — and a failure is reported as output too, so the model can correct its own code rather than failing the turn.

Two pieces are injected. `Sandbox` decides where the code runs: `Sandbox.inProcess` evaluates via `new AsyncFunction` here and now, which is NOT a security boundary — the code is compiled in the host realm and can reach host globals, and the timeout abandons a running evaluation rather than stopping it. `WorkerSandbox` runs the same code in a worker thread instead, over an Effect RPC channel back to the host, which is what makes a timeout enforceable: the host TERMINATES the thread, so an evaluation that outran its budget stops — including a synchronous loop, which no in-process timeout can interrupt at all. Because every binding call and result crosses that channel by structured clone, a binding must be a function over plain data: live objects travel as a snapshot and are resolved back by id, and a function passed as an argument cannot cross, which is why `PlainDialect`'s `update` now takes a patch (`update(obj, { status: 'done' })`) as well as a mutator. A worker bounds time and isolates crashes; it is still not a security boundary, since it shares the host's permissions. Install it with `WorkerSandbox.layer()` or `CodeModeOptions.sandbox`, and pass `spawn` for a runtime whose worker is not `node:worker_threads`. `Dialect` decides what the model writes: `PlainDialect` is a small async facade (`await query(...)`, `update(obj, patch)`, `await ops.thing(input)`) whose bindings are plain functions over plain data, so it survives an out-of-process sandbox; `EffectDialect` is the repo's own ECHO API as an `Effect.gen` body (`yield* Database.query(Filter.type(types['...'])).run`), which reads like committed code but pins the sandbox to this process.

Opt in with `makeCodeModeTurnProducer({ dialect })` as `AgentProcessOptions.makeTurnProducer` (or `AgentService.Options.makeTurnProducer`); the process's queue, alarms, redelivery, delegation and hydration are unchanged, and the default `AiSession` producer still applies when it is not set.
