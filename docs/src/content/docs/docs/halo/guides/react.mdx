This guide wires HALO into a React app. At the end, your components show the identity, its devices, its spaces and
their members, and follow an invitation.

`@dxos/halo-react` reads HALO from React components. Each hook follows one `@dxos/halo` stream and re-renders when it
emits, so a component shows the current identity, devices or members without subscribing itself.

## Set up the provider

`HaloProvider` takes the two HALO services, `Identity.Service` and `Space.Service`, in an Effect `Context`. Build the
context from a `Client` with `makeIdentityService` and `makeSpaceService` from `@dxos/halo-adapter-client`. Then wrap
the part of the app that uses the hooks.

<Snippet file="halo-guide-react" region="provider" lang="tsx" />

`services` is built once, outside any component, so every hook reads the same two services. Every hook except
`useInvitationFlow` throws when it runs outside `HaloProvider`.

## The identity

`useIdentity` returns the identity, or `undefined` before one exists. It has the current value on the first render.
`useDevices` and `useCredentials` return the identity's devices and credentials.

**Example** (Showing the identity, its devices and its recovery credentials)

<Snippet file="halo-guide-react" region="identity" lang="tsx" />

`recovery` counts only the credentials that carry `recovery` and are not revoked. `useCredentials` returns every
credential the identity holds, and a revoked recovery credential stays in the list.

## Spaces and members

`useSpaces` returns the spaces that are ready. Pass `{ all: true }` when you want every space. `useSpace` finds one by
id, and `useMembers` returns a space's members.

**Example** (Listing each space with its members)

<Snippet file="halo-guide-react" region="spaces" lang="tsx" />

`Members` falls back to `member.did` because a display name is optional. `useSpace` returns `undefined` for an id the
identity has no space for, so the name is read as `space?.name`.

## Invitations

An invitation in progress is a flow, an `Invitation.Flow` handle that `Space.share` or `Identity.share` returns. Start
one by running that Effect with the services you gave the provider.

`useInvitationFlow` follows the flow, and returns its latest event and its code. It needs no provider, because a flow
carries what it needs.

`useSpaceInvitations` and `useHaloInvitations` list the flows this device has open.

**Example** (Starting an invitation and showing its codes)

`code` is the invitation code to send, and `Invite` shows it as soon as the flow has one. `event.authCode` is the
authorization code to tell the guest. Only the host's flow carries it, and only at `readyForAuthentication`.

## Hooks at a glance

| Hook                                       | Returns                                       |
| ------------------------------------------ | --------------------------------------------- |
| `useIdentity`                              | The identity, or `undefined`                  |
| `useDevices` `useCredentials`              | The identity's devices and credentials        |
| `useSpaces` `useSpace`                     | Spaces, and one space by id                   |
| `useMembers`                               | A space's members                             |
| `useContacts`                              | Everyone you share a space with, once each    |
| `useSpaceInvitations` `useHaloInvitations` | Open space and device invitations             |
| `useInvitationFlow`                        | One flow's latest event and code              |
