`Identity` manages the user on this device. Use it for the identity itself, its profile, its devices, its recovery
credentials and the credentials it grants to services.

Every function is an Effect or a Stream that needs `Identity.Service`. Run one with `Effect.runPromise` once the
service is provided.

## Read the identity

`getSnapshot` reads the identity once, as an `Option` that is empty before an identity exists. Use it when you need
the value now and no updates.

`identity` is a stream that emits the current value, then each change. Use it when your code has to follow the
identity.

## Recovery credentials

- `createRecoveryCredential` with no options returns a recovery code. Pass `externalKey` to register a passkey
  instead.
- `recover` gets the identity back on a new device. It takes a recovery code, a passkey assertion, the token from a
  DXOS account's sign-in email, or the proof from an OAuth sign-in. EDGE checks it and admits the device.
- `revokeRecoveryCredential` withdraws a credential by its lookup key. HALO refuses to revoke the last active one.

**Example** (Creating, using and revoking a recovery code)

<Snippet file="halo-guide-identity" region="recovery" />

In this example, `backup` creates a recovery code and logs it for the user to write down. `restore` passes that code
to `recover` on a new device, and `revoke` withdraws a credential by its lookup key.

<Aside type="caution">
  Recovery needs a DXOS account. EDGE stores recovery credentials only for identities linked to an account, and for now
  you can create an account only through [Composer](https://composer.space).
</Aside>

## Service access and API tokens

- `grantServiceAccess` writes a credential that lets the identity use an EDGE or Hub service. See
  [Identity services](/docs/edge/concepts/identity-services/).
- `createApiToken` mints a token a CLI or a server can use to act as the identity. The token's secret is returned
  once, so store it straight away.
- `getEdgeIdentity` is the identity as EDGE authenticates it. Use it for an HTTP or WebSocket client.

## Members at a glance

| Member                                                          | Summary                                  |
| --------------------------------------------------------------- | ---------------------------------------- |
| `Service`                                                       | The Effect service                       |
| `getSnapshot` `identity` `atom`                                 | The identity: once, as a stream, as an Atom |
| `create` `updateProfile`                                        | Make the identity and edit its profile   |
| `getDevicesSnapshot` `devices`                                  | The identity's devices                   |
| `share` `join` `invitations`                                    | Device invitations                       |
| `createRecoveryCredential` `recover` `revokeRecoveryCredential` | Recovery                                 |
| `requestRecoveryChallenge`                                      | The challenge a passkey signs            |
| `credentials`                                                   | The credentials the identity holds       |
| `grantServiceAccess` `createApiToken` `getEdgeIdentity`         | Access to EDGE and Hub services          |

The full list is in the [API reference](/docs/halo/resources/api-reference/).

## Errors

Every function that can fail fails with `IdentityError`, whose message says what went wrong. Handle it by its tag:

<Snippet file="halo-guide-identity" region="errors" />

Here, `safeRename` catches the error from `rename` and logs its message.

`@dxos/halo` also exports the errors Keyhive raises when it checks a membership operation. They name why a delegation or a
revocation was refused:

| Error                    | Raised when                                                              |
| ------------------------ | ------------------------------------------------------------------------ |
| `NotAuthorizedError`     | The acting member lacks the access, such as revoking without seniority   |
| `UnknownPrincipalError`  | The identity, device or group named is not known                         |
| `InvalidSignatureError`  | A signed operation fails verification                                    |
| `MissingDependencyError` | An operation refers to earlier operations that have not arrived          |
