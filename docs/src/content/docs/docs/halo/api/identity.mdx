`Identity` manages the user on this device: the identity itself, its profile, its devices, its recovery credentials and
the credentials it grants to services. Every function is an Effect or a Stream that needs `Identity.Service`. Run one with
`Effect.runPromise` once the service is provided.

## Get the service

`layerClient` from `@dxos/halo-adapter-client` provides `Identity.Service` and `Space.Service` from a `Client`.

<Snippet file="halo-guide-identity" region="layer" />

## Read the identity

`getSnapshot` reads it once, as an `Option` that is empty before an identity exists. `identity` is a stream that emits the
current value, then each change.

<Snippet file="halo-guide-identity" region="read" />

Code outside Effect can take the service itself and use its synchronous methods: `subscribe` calls back with each change
and returns a function that stops it. `Identity.atom` gives the same value as an Atom.

<Snippet file="halo-guide-identity" region="service" />

## Create an identity and update its profile

`create` makes the identity and this device its first member, and stores the device's key on the device. `updateProfile`
changes the display name and any profile data, such as an avatar.

<Snippet file="halo-guide-identity" region="create" />

`personalSpaceId` is the id of the identity's [personal space](/docs/halo/concepts/identities-devices/), or nothing before
the identity exists.

<Snippet file="halo-guide-identity" region="personal-space" />

## Devices

`getDevicesSnapshot` lists the identity's devices once, and `devices` streams the list. Each device has a key, a kind, a
presence and, when set, a label.

<Snippet file="halo-guide-identity" region="devices" />

To add one, `share` starts a device invitation and `join` accepts it on the new device. Both return an
[`Invitation.Flow`](/docs/halo/api/invitation/). `invitations` streams the device invitations this device has open.

<Snippet file="halo-guide-identity" region="share" />

## Recovery credentials

`createRecoveryCredential` with no options returns a recovery code. Pass `externalKey` to register a passkey instead.
`recover` admits a new device with a recovery code, a passkey assertion or an OAuth token, and
`revokeRecoveryCredential` withdraws a credential by its lookup key. HALO refuses to revoke the last active one.

<Snippet file="halo-guide-identity" region="recovery" />

<Aside type="caution">
  Recovery needs a DXOS account. EDGE stores recovery credentials only for identities linked to an account, and for now
  you can create an account only through [Composer](https://composer.space).
</Aside>

A passkey signs a challenge before `recover`. `requestRecoveryChallenge` gets it from EDGE;
[Passkey recovery](/docs/halo/guides/passkey-recovery/) walks through the whole ceremony.

<Snippet file="halo-guide-identity" region="challenge" />

## Credentials

`credentials` streams the credentials the identity holds. A recovery credential carries its kind, label, lookup key and
whether it has been revoked.

<Snippet file="halo-guide-identity" region="credentials" />

## Service access and API tokens

`grantServiceAccess` writes a credential that lets the identity use an EDGE or Hub service (see [Identity services](/docs/edge/concepts/identity-services/)). `createApiToken` mints a token
a CLI or a server can use to act as the identity. The token's secret is returned once, so store it straight away.
`getEdgeIdentity` is the identity as EDGE authenticates it, for an HTTP or WebSocket client.

<Snippet file="halo-guide-identity" region="access" />

## Members at a glance

| Member                                                          | Summary                                  |
| --------------------------------------------------------------- | ---------------------------------------- |
| `Service`                                                       | The Effect service                       |
| `getSnapshot` `identity` `atom`                                 | The identity: once, as a stream, as an Atom |
| `create` `updateProfile`                                        | Make the identity and edit its profile   |
| `personalSpaceId`                                               | The identity's personal space            |
| `getDevicesSnapshot` `devices`                                  | The identity's devices                   |
| `share` `join` `invitations`                                    | Device invitations                       |
| `createRecoveryCredential` `recover` `revokeRecoveryCredential` | Recovery                                 |
| `requestRecoveryChallenge`                                      | The challenge a passkey signs            |
| `credentials`                                                   | The credentials the identity holds       |
| `grantServiceAccess` `createApiToken` `getEdgeIdentity`         | Access to EDGE and Hub services          |

The full list is in the [API reference](/docs/halo/resources/api-reference/).

## Errors

Every function that can fail fails with `IdentityError`, whose message says what went wrong. Handle it by its tag:

<Snippet file="halo-guide-identity" region="errors" />

`@dxos/halo` also exports the errors Keyhive raises when it checks a membership operation. They name why a delegation or a
revocation was refused:

| Error                    | Raised when                                                              |
| ------------------------ | ------------------------------------------------------------------------ |
| `NotAuthorizedError`     | The acting member lacks the access, such as revoking without seniority   |
| `UnknownPrincipalError`  | The identity, device or group named is not known                         |
| `InvalidSignatureError`  | A signed operation fails verification                                    |
| `MissingDependencyError` | An operation refers to earlier operations that have not arrived          |
