An invitation lets a device into an identity, or a person into a space. You never make one with this namespace directly:
`Identity.share`, `Identity.join`, `Space.share` and `Space.join` each return an `Invitation.Flow`, and `Invitation` drives
that flow from either side. Its functions need no service, because they act on the flow handle itself.

## Choose how the invitation works

`share` takes options that decide who can redeem the invitation and how:

- `authMethod`: `'shared-secret'` makes the guest enter the authorization code the host shows; `'none'` admits anyone with
  the invitation code; `'known-public-key'` admits only a guest whose key the host names.
- `type`: `'interactive'` needs host and guest online together; `'delegated'` can be redeemed while the host is offline;
  `'multiuse'` admits more than one guest.
- `target`: with `'known-public-key'`, the key or DID of the one guest it admits.

## Read the code

`Invitation.code` is the string to send to the guest, usually inside a link or a QR code.

## Follow a flow

`Invitation.events` streams the flow's progress: `connecting`, `connected`, `readyForAuthentication`, `authenticating`,
then one of `success`, `cancelled` or `error`. On the host, `readyForAuthentication` carries the authorization code to
show. On the guest, it is the moment to call `Invitation.authenticate`.

## Cancel a flow

Either side can cancel. The host can list its open flows with `Space.invitations` or `Identity.invitations`.

## Members at a glance

| Member            | Summary                                             |
| ----------------- | --------------------------------------------------- |
| `Flow`            | An invitation in progress, host or guest side       |
| `code`            | The invitation code to send                         |
| `events`          | The flow's progress as a stream                     |
| `authenticate`    | Send the authorization code                         |
| `cancel`          | End the flow                                        |
| `ShareOptions`    | `authMethod`, `type`, `multiUse` and `target`       |

The full list is in the [API reference](/docs/halo/resources/api-reference/).

## Errors

`code` and `authenticate` fail with `InvitationError`, for example when the guest sends a wrong authorization code. The
flow also emits an `error` event, so a UI following `events` needs no separate handler.

<Snippet file="halo-guide-invitation" region="errors" />

`share` and `join` fail with the error of the namespace that started the flow: `IdentityError` for a device invitation and
`SpaceError` for a space invitation.
