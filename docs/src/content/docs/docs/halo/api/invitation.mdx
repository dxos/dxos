An invitation lets a device into an identity, or a person into a space. `Invitation` drives an invitation that is in
progress, from either side.

You never make an invitation with this namespace directly. `Identity.share`, `Identity.join`, `Space.share` and
`Space.join` each return an `Invitation.Flow`, and you pass that flow to the functions here. They need no service,
because they act on the flow handle itself.

## Choose how the invitation works

`share` takes options that decide who can redeem the invitation and how.

`authMethod` is how the guest proves it is the intended guest:

- `'shared-secret'` makes the guest enter the authorization code the host shows.
- `'none'` admits anyone with the invitation code.
- `'known-public-key'` admits only a guest whose key the host names.

`type` says whether the host has to be online:

- `'interactive'` needs host and guest online together.
- `'delegated'` can be redeemed while the host is offline.
- `'multiuse'` is deprecated. Set `multiUse` instead.

`multiUse` says how many guests can redeem the invitation. By default it ends when the host admits the first guest.
Set `multiUse` to `true` when more than one guest has to redeem the same code.

`target` goes with `'known-public-key'`. It is the key or DID of the one guest the invitation admits.

## Follow a flow

`Invitation.events` streams the flow's progress: `connecting`, `connected`, `readyForAuthentication`, `authenticating`,
then one of `success`, `cancelled` or `error`. Use it when your UI has to show where the invitation stands.

`readyForAuthentication` means something different on each side:

- On the host, it carries the authorization code to show.
- On the guest, it is the moment to call `Invitation.authenticate`.

## Members at a glance

| Member            | Summary                                             |
| ----------------- | --------------------------------------------------- |
| `Flow`            | An invitation in progress, host or guest side       |
| `code`            | The invitation code to send                         |
| `events`          | The flow's progress as a stream                     |
| `authenticate`    | Send the authorization code                         |
| `cancel`          | End the flow                                        |
| `ShareOptions`    | `authMethod`, `type`, `multiUse` and `target`       |

The full list is in the [API reference](/docs/halo/resources/api-reference/).

## Errors

`code` and `authenticate` fail with `InvitationError`:

- `code` fails when the flow ends before its code is ready to send.
- `authenticate` fails when the flow takes no authorization code, as the host's flow does not.

<Snippet file="halo-guide-invitation" region="errors" />

Here, `safeCode` catches `InvitationError` by its tag and logs the message.

A wrong authorization code does not fail `authenticate`. The guest's flow goes back to `readyForAuthentication`, and
the guest can send another code. After three wrong codes the flow ends with an `error` event, so a UI following
`events` needs no separate handler.

`share` and `join` fail with the error of the namespace that started the flow: `IdentityError` for a device invitation and
`SpaceError` for a space invitation.
