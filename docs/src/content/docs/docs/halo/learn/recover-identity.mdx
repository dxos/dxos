By the end of this page Alice has a recovery code, and with it gets her name, spaces and contacts back on a new laptop.

<Aside type="caution" title="Account required">
  Recovery needs a DXOS account. EDGE stores recovery credentials only for identities linked to an account. For now,
  you can create an account only through [Composer](https://composer.space).
</Aside>

## Background

Alice's laptop is stolen, and her phone was in the same bag. Her identity is made of keys that those devices held, and
no server can reset a key. To let a new device in, she needs a key that was never on a device.

A **recovery key** is that key. A **recovery code** is one way to keep it, as twelve words that the key is made from. A
passkey is another. See [Passkey recovery](/docs/halo/guides/passkey-recovery/).

Making a recovery code writes a **recovery credential**, a signed record on the identity that names the recovery key.
In Keyhive's terms the key becomes a member of the identity's group. Each recovery credential also has a **lookup
key**, a public value that names it. We make a code in step 1, and revoke one by its lookup key in step 3.

Recovery goes through [EDGE](/docs/edge/concepts/identity-services/), DXOS's always-online peer. In step 4, the new
device asks EDGE for a challenge and signs it with the recovery key. EDGE checks the signature against the identity's
recovery credentials. The identity's agent device, whose key EDGE holds, then signs the credential that admits the new
device, and EDGE returns it.

The new device is a new member of the same identity, with the same DID. It syncs its spaces from EDGE and from anyone
online.

HALO shows a recovery code once and keeps only the public half of its key. It also refuses to revoke your last active
recovery credential, so we make a second code before we revoke the first.

## Steps

<Steps>

1. **Make a recovery code.** On the Recovery tab, **Make a recovery code** calls `handleCreate`.
   `Identity.createRecoveryCredential` makes the recovery key, writes its recovery credential, and returns the words.

   <Snippet file="halo-tutorial/app/Recovery" region="create" lang="tsx" />

2. **List your codes.** The Recovery tab lists the recovery credentials that still work. `useCredentials` returns
   every credential the identity holds, read from the `Identity.credentials` stream.

   Each credential carries `issuanceDate`, the date it was issued. A recovery credential also carries `recovery`, which
   has its kind, a label, its lookup key and whether it was revoked.

   <Snippet file="halo-tutorial/app/Recovery" region="list" lang="tsx" />

   `recovery.revoked` is the test that matters. A revoked credential stays in the stream, marked, because the record
   of it is never deleted.

3. **Revoke a code.** **Revoke** beside a code calls `handleRevoke` with that credential's lookup key, and
   `Identity.revokeRecoveryCredential` revokes it. Revoke a code you think someone has seen.

   <Snippet file="halo-tutorial/app/Recovery" region="revoke" lang="tsx" />

   `revokeRecoveryCredential` fails when the code is your last one. `handleRevoke` checks `codes.length` to tell that
   failure from any other, and shows a message that says to make another code first.

4. **Recover on a new device.** On a device with no identity, **Recover with a code** asks for the words and calls
   `handleRecover`. `Identity.recover` signs EDGE's challenge with the key made from the words, and returns the
   identity.

   <Snippet file="halo-tutorial/app/Welcome" region="recover" lang="tsx" />

</Steps>

## Try it

Open **Recovery** on Alice's laptop and make a code. Make a second one, then revoke the first. Try revoking the last one
too, and HALO refuses.

<Aside title="Recovering on the real network">
  The devices on these pages run in your browser with no network, and recovering needs EDGE, so step 4 does not run
  here. The finished app on StackBlitz runs on the real network. An identity you create there has no DXOS account, so
  EDGE does not store its recovery credentials, and `Identity.recover` fails for it.

  Fork the app to read and change the code. To see a recovery succeed, the identity needs an account, as the caution
  at the top of this page says.
</Aside>

## What you can do now

You can make and revoke recovery codes, and recover an identity on a new device. That is the whole contact book. From
here, [Identities and devices](/docs/halo/concepts/identities-devices/) starts the core concepts, which explain the
model behind the app. [Identity](/docs/halo/api/identity/) starts the API pages, which cover the rest of `@dxos/halo`.
