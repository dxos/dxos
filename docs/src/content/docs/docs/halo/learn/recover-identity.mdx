By the end of this page Alice has a recovery code, and with it gets her name, spaces and contacts back on a new laptop.

<Aside type="caution" title="Account required">
  Recovery needs a DXOS account. EDGE stores recovery credentials only for identities linked to an account. For now,
  you can create an account only through [Composer](https://composer.space).
</Aside>

## Background

With an account, you reset a lost password by email. A HALO identity is made of keys that your devices hold, and no
server can reset a key. If you lose every device, you need another key to let a new device in. A **recovery
credential** is that key, kept outside every device.

A **recovery code** is one such key, written as twelve words. Making it adds the key to the identity's group as a
member, the same way a device is added. This means the key can admit a new device later. We make a code in step 1.

Recovery goes through [EDGE](/docs/edge/concepts/identity-services/). The new device asks EDGE for a challenge and
signs it with the key derived from the words. EDGE checks the signature against the identity's recovery credentials
before it admits the device.

The new device is a new member of the same identity, with the same DID. It syncs its spaces from EDGE and from anyone
online.

HALO shows a recovery code once and keeps only its public half. It refuses to revoke the last code you have, so make
the new one first. A passkey works the same way. See [Passkey recovery](/docs/halo/guides/passkey-recovery/).

## Steps

<Steps>

1. **Make a recovery code.** `Identity.createRecoveryCredential` makes the key, adds it to the identity, and returns the
   words. **Make a recovery code** on the Recovery tab calls this.

   <Snippet file="halo-tutorial/app/Recovery" region="create" lang="tsx" />

   Notice that `handleCreate` keeps `recoveryCode` to show it. HALO returns the words only this once.

2. **List your codes.** `useCredentials` returns the identity's credentials and re-renders when one is written. It
   follows `Identity.credentials`.

   Each credential carries `issuanceDate`, the date it was issued. A recovery credential also carries `recovery`, which
   has its kind, a label, a lookup key and whether it was revoked. The Recovery tab lists the ones still active.

   <Snippet file="halo-tutorial/app/Recovery" region="list" lang="tsx" />

   Notice that `codes` keeps each credential's `recovery` fields and adds its `issuanceDate` to them.

3. **Revoke a code.** `Identity.revokeRecoveryCredential` takes the lookup key. Revoke a code you think someone has
   seen.

   <Snippet file="halo-tutorial/app/Recovery" region="revoke" lang="tsx" />

   If the code is your last one, the call fails, and `handleRevoke` shows a message that says to make another first.

4. **Recover on a new device.** On a device with no identity, `Identity.recover` takes the words and gets the identity
   back. **Recover with a code** calls this.

Open **Recovery** on Alice's laptop and make a code. Make a second one, then revoke the first. Try revoking the last one

## What you can do now

You can make and revoke recovery codes, and recover an identity on a new device. That is the whole contact book. From
here, [Core concepts](/docs/halo/concepts/identities-devices/) explains the model behind it, and the
[API](/docs/halo/api/identity/) pages cover the rest of `@dxos/halo`.
