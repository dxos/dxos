In this learning path we build one app, a contact book. In it, you give yourself a name, keep a few spaces, and
invite people into them. Your contacts are the people you share a space with.

## What an identity is

Everything the contact book shows comes from one **identity** per person. An identity stands for a person in HALO, and
it has four parts:

- **A DID.** A DID is a decentralized identifier, such as `did:halo:BA25QRC2…`. Peers know the identity by this one
  name, on every device and in every space.
- **A profile.** The profile holds the identity's display name and any other data the app adds, such as an avatar.
  Every space the identity is in shows it.
- **Members.** HALO is built on [Keyhive](https://github.com/inkandswitch/keyhive), a system for access control
  between peers. In Keyhive an identity is a **group** of keys. Each device holds its own key and acts for the
  identity with it. The key behind a recovery code is a member too, kept off every device.
- **Spaces.** A space is a group as well, and the identity is one of its members, with an access level that says what
  it may do there. Each device of the identity acts for it in every space it belongs to.

A device makes the identity's keys, and no server issues them. Two signed statements change who is in a group. A
**delegation** admits a member, and a **revocation** removes one. Every peer checks each of them for itself.

[Identities and devices](/docs/halo/concepts/identities-devices/) describes the model in full.

## The finished app

The contact book below runs for Alice, Bob and Carol. All three are in Book club, and Alice and Carol are also in
Climbing.

Open Contacts on Alice's device to see Bob and Carol with the spaces each shares with her. You can make a new space,
invite someone into it, or switch a device offline. MESH's [Presence](/docs/mesh/concepts/presence/) explains how
peers notice that a device has gone offline.

Each page of the learning path adds one part of the app:

| Page | Files | What it adds |
| --- | --- | --- |
| [Your profile](/docs/halo/learn/your-profile/) | `App.tsx`, `Welcome.tsx`, `ContactBook.tsx`, `Profile.tsx` | A client, an identity with a profile, and renaming |
| [Your spaces](/docs/halo/learn/your-spaces/) | `Spaces.tsx`, `ContactBook.tsx` | Named spaces, and a list to switch between them |
| [Invite people](/docs/halo/learn/invite-people/) | `Invitations.tsx` | Invite and Join, with an authorization code |
| [Your contacts](/docs/halo/learn/your-contacts/) | `Contacts.tsx` | Everyone you share a space with, and removing them |
| [Add a device](/docs/halo/learn/add-device/) | `Devices.tsx`, `Welcome.tsx` | Your phone, with the same name, spaces and contacts |
| [Recover an identity](/docs/halo/learn/recover-identity/) | `Recovery.tsx`, `Welcome.tsx` | A recovery code, and your identity back on a new device |

The code uses [Effect](https://effect.website/). Each `@dxos/halo` function returns an `Effect`, which describes a
piece of work and runs only when you run it, or a `Stream`, a series of values over time. Both need a service, the
object that does the work, and a `HaloProvider` from `@dxos/halo-react` holds each device's services.

A component reads state with that package's hooks, such as `useIdentity` and `useSpaces`. To change something, it takes
the services with `useHaloServices`, gives them to the Effect with `Effect.provide`, and runs it with
`Effect.runPromise`.

The samples show each part in the component that uses it, with the rest of the component folded away.
