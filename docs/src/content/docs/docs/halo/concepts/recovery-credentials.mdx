A recovery credential is a key outside every device that the identity has admitted as one of its members. A new device
that signs with the key joins the identity. This means the user gets their identity back after losing every device.

<Aside type="caution">
  Recovery needs a DXOS account. EDGE stores recovery credentials only for identities linked to an account, and for now
  you can create an account only through [Composer](https://composer.space).
</Aside>

## Model

In a web app, a user who loses their password asks the server for a reset. A HALO identity is made of keys, and no
server can reset a key. Instead, the user makes a recovery credential ahead of time.

**Recovery kinds.** The kind says where the key lives:

| Kind            | The key lives                                               |
| --------------- | ----------------------------------------------------------- |
| `recovery-code` | In a phrase of words HALO generates and the user writes down |
| `passkey`       | In the platform's passkey store, behind the user's biometrics or PIN |
| `oauth`         | Behind an account with an OAuth provider                    |

**The recovery key is a member.** Creating a recovery credential is a delegation, like admitting a device. The
identity's group gains a member whose key the user holds outside every device. Revoking the credential removes that
member.

**The recovery challenge.** Recovery runs through [EDGE](/docs/edge/concepts/identity-services/), in these steps:

1. The new device asks for a challenge with `Identity.requestRecoveryChallenge`.
2. The device signs the challenge with the recovery key, and sends the signature back with `Identity.recover`.
3. EDGE checks the signature against the identity's recovery credentials. If it matches one, EDGE returns the signed
   credential that admits the new device.

For a recovery code, `recover` derives the key from the phrase and does the signing itself.

The recovery key signs only the challenge. Its private half stays with the user, and EDGE holds the public half.

The credential that admits the new device comes from EDGE. EDGE can hold a key for an identity that grants it one, as
a device of that identity. See [Identities and devices](/docs/halo/concepts/identities-devices/).

**What comes back.** The recovered device has the same identity and DID. It is a new device of that identity, so it syncs
the identity's spaces from EDGE and from any other members.

**Credentials.** An identity holds signed credentials. These are the statements that admit its devices, its recovery
credentials, and service access credentials. `Identity.credentials` is a stream of them, with the current set first.

A recovery credential carries its kind, its label, its lookup key and whether it has been revoked.

`grantServiceAccess` writes a credential that lets the identity use an EDGE or Hub service. `createApiToken` mints a
token for a CLI or a server to act as the identity.

## Behavior

- Creating a recovery code shows the phrase once. HALO keeps only the public half.
- A revoked recovery credential no longer admits devices.
- HALO refuses to revoke the last recovery credential that is still active. Make the new one first.
- Recovery needs a network connection to EDGE.

## Limits

- HALO cannot show a lost recovery code again. If every device is lost too, the identity comes back only through
  another recovery credential, or through its DXOS account. `recover` also takes the token from the account's sign-in
  email. With none of these, the identity is gone.
- Anyone who holds a recovery code can take over the identity. Revoke a code you think has leaked. If it is your last
  active recovery credential, make a new one first, because HALO refuses to revoke the last one.
