---
title: Recovery and credentials
description: How an identity survives the loss of its devices, and what credentials it holds.
---

A recovery credential is a key outside every device that the identity has authorized to admit a new device, so the user can
get their identity back after losing all of them.

## Model

**Recovery kinds.**

| Kind            | The key lives                                               |
| --------------- | ----------------------------------------------------------- |
| `recovery-code` | In a phrase of words HALO generates and the user writes down |
| `passkey`       | In the platform's passkey store, behind the user's biometrics or PIN |
| `oauth`         | Behind an account with an OAuth provider                    |

**The recovery challenge.** Recovery runs through EDGE. The new device asks for a challenge with
`Identity.requestRecoveryChallenge`, signs it with the recovery key, and sends the signature back with `Identity.recover`.
For a recovery code, `recover` derives the key from the phrase and does the signing itself. EDGE checks the signature
against the identity's recovery credentials and admits the new device.

**What comes back.** The recovered device has the same identity and DID. It is a new device of that identity, so it syncs
the personal space and the identity's other spaces from EDGE and from any other members.

**Credentials.** An identity holds signed credentials: the statements that admit its devices, its recovery credentials,
and service access credentials. `Identity.credentials` lists them. `grantServiceAccess` writes a credential that lets the
identity use an EDGE or Hub service, and `createApiToken` mints a token for a CLI or a server to act as the identity.

## Behavior

- Creating a recovery code shows the phrase once. HALO keeps only the public half.
- A revoked recovery credential no longer admits devices.
- Recovery needs a network connection to EDGE.

## Limits

- A lost recovery code, with every device lost too, means the identity is gone. There is no reset.
- Anyone who holds a recovery code can take over the identity. Revoke a code you think has leaked, then make a new one.
