Recovery is how an identity comes back after its devices are lost. The user registers a recovery key ahead of time,
kept off every device, and later uses it to bring a new device into the identity.

<Aside type="caution" title="Account required">
  Recovery needs a DXOS account. EDGE stores recovery credentials only for identities linked to an account, and for now
  you can create an account only through [Composer](https://composer.space).
</Aside>

## Model

Every device holds a key of its own, and no server can reset a key. What is left when every device is gone? Only a
key that was never on a device, which the user set up ahead of time.

A **recovery key** is that key. A **recovery credential** is the signed record that registers a recovery key with the
identity. It names the key's public half, and it carries a kind, a label, a lookup key and whether it has been
revoked.

A **lookup key** is a public value that names one recovery credential. You pass it to revoke the credential, and a
new device sends it to say which credential it is answering to.

The kind says where the recovery key lives:

| Kind            | The key lives                                               |
| --------------- | ----------------------------------------------------------- |
| `recovery-code` | In a phrase of words HALO generates and the user writes down |
| `passkey`       | In the platform's passkey store, behind the user's biometrics or PIN |
| `oauth`         | Behind an account with an OAuth provider                    |

**The recovery key is a member.** In Keyhive's terms, writing a recovery credential is a delegation, like admitting a
device. The identity's group gains a member whose key the user holds outside every device. Revoking the credential
removes that member.

**The recovery challenge.** Recovery runs through [EDGE](/docs/edge/concepts/identity-services/), DXOS's
always-online peer, in these steps:

1. The new device asks for a challenge with `Identity.requestRecoveryChallenge`.
2. The device signs the challenge with the recovery key, and sends the signature back with `Identity.recover`.
3. EDGE checks the signature against the identity's recovery credentials. If it matches one, the identity's agent
   device signs the credential that admits the new device, and EDGE returns it.

For a recovery code, `recover` asks for the challenge, makes the key from the phrase and signs, all in one call.

The recovery key signs only the challenge. Its private half stays with the user, and EDGE holds the public half.

The credential that admits the new device needs a key that can act for the identity, and every device is gone. By
default no server holds such a key. An identity linked to a DXOS account has granted EDGE one, as an agent device, and
EDGE signs with it. An identity without an agent device cannot be recovered. See
[Identities and devices](/docs/halo/concepts/identities-devices/).

**What comes back.** The recovered device has the same identity and DID. It is a new device of that identity, so it syncs
the identity's spaces from EDGE and from any other members.

An identity holds signed **credentials**. These are the statements that admit its devices, its recovery credentials,
and service access credentials. `Identity.credentials` is a stream of them, with the current set first.

`grantServiceAccess` writes a credential that gives the identity access to a service on EDGE or on Hub, the EDGE
service that keeps DXOS accounts. `createApiToken` mints a token for a CLI or a server to act as the identity.

## Behavior

- Creating a recovery code shows the phrase once. HALO keeps only the public half of the key.
- A revoked recovery credential no longer admits devices.
- HALO refuses to revoke the last recovery credential that is still active. To replace it, register the new recovery
  key first.
- Recovery needs a network connection to EDGE.

## Limits

- HALO cannot show a lost recovery code again. If every device is lost too, the identity comes back only through
  another recovery key, or through its DXOS account. `recover` also takes the token from the account's sign-in
  email. With none of these, the identity is gone.
- Anyone who holds a recovery code can take over the identity. Revoke a code you think has leaked.
