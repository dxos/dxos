---
title: Identities and devices
description: An identity is a Keyhive group named by a DID; its devices are its members.
---

An identity stands for one user. In [Keyhive](https://www.inkandswitch.com/keyhive/notebook/), which HALO is built on, it
is a group named by a DID, and its members are the user's devices.

## Model

In most web apps, a user is a row in a server's database, and the server decides who is signed in. A HALO identity has
no such server. The client makes the identity's keys on the device, and no server issues the identity.

By default, no server holds a key that can act for the identity. You can grant a server that access, so that it
holds a key for you, and EDGE provides this as a service.

When you grant it, EDGE runs an agent for the identity. The agent is one of the identity's devices, of kind
`agent-managed`, and EDGE holds its key. Like any device, the agent can act for the identity.

Composer grants this when the identity is linked to a DXOS account.
[Recovery and credentials](/docs/halo/concepts/recovery-credentials/) describes EDGE's part in a recovery.

**Identity.** `Identity.create` makes the group and its first member, which is the device the code runs on. Other
members and services refer to the user by the DID, such as `did:halo:BA25QRC2FEWCSAMRP4RZL65LWJ7352CKE`. The identity
also has a profile, which holds a display name and free-form data such as an avatar.

**Device.** Each client storage, such as one browser profile on one site, has its own device key. A device becomes a
member of the identity through a **delegation**. A delegation is a statement, signed by a device that is already a
member, that admits the new key. Removing a device is a **revocation**.

The first device creates the identity. Later devices join through a
[device invitation](/docs/halo/concepts/invitations/).

A device signs the changes it makes, and peers check the signature against the identity's members.

Each device reports:

| Field      | Meaning                                                                 |
| ---------- | ----------------------------------------------------------------------- |
| `kind`     | `browser`, `native`, `mobile`, `agent` and `agent-managed` for hosted agents, or `unknown` |
| `presence` | `online`, `offline`, or `removed` once the device has been evicted      |
| `current`  | Whether this is the device the code runs on                             |

An identity with two devices looks like this:

```text
identity (did:halo:…)
├── device: laptop browser   ← created the identity
└── device: phone            ← joined by invitation
```

## Behavior

- You need no network to create an identity.
- A new device receives the identity's spaces by syncing with the devices it was admitted by, or through [EDGE](/docs/edge/concepts/replication/).
- A device that is revoked stops being trusted for new changes. Changes it signed before the revocation stay valid.

## Limits

- If every device is lost, the identity comes back only through
  [recovery](/docs/halo/concepts/recovery-credentials/), and recovery needs a DXOS account. With no account, the
  identity is gone. No one, including DXOS, can restore it, and its spaces are reachable only through other members.
- A [recovery key](/docs/halo/concepts/recovery-credentials/) is a member of the identity too. A new device that signs
  EDGE's challenge with it joins the identity when no device is left.
- Clearing a browser's site data deletes that device's keys. The device must join again as a new device.
