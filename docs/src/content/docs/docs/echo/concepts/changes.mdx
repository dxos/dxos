Every write to an object is a change. Changes from different peers merge without asking either of them, and each
object keeps the history of its changes. A branch lets a set of changes wait apart from the main line until you merge
them.

## Model

In a client-server app, the server holds the one copy of a record, and every write goes through it. In ECHO, each
object lives in an [Automerge](https://automerge.org/) document, a CRDT, and a peer writes to its own copy. The write
is finished when the call returns. <SpecCite item="org.dxos.echo.query#F-2.1" />

Peers then exchange changes. Every peer that has seen the same changes ends up with the same state, whatever order the
changes arrived in.

What "merged" means depends on the kind of value:

| Concurrent change                                | Result                                                       |
| ------------------------------------------------ | ------------------------------------------------------------ |
| Different fields of one object                   | Both writes kept                                             |
| The same scalar field, such as a status          | One value wins, the same on every peer                       |
| A whole string assigned twice                    | One string wins, as with any scalar                          |
| Characters inserted or deleted with `Text`       | Both edits kept, interleaved                                 |
| Items inserted into one array                    | Both kept; the order of the two new items is decided by ECHO |
| One peer edits an object another removes         | The removal stands                                           |

The table explains the choice between assigning a string and editing it with `Text`:

- Assignment replaces the value.
- `Text.splice` and `Text.update` change characters. Use them when two people may type in the same field, so that
  both keep their work.

## Behavior

- When you write locally, the write shows in query results and reaches subscribers before the writing call returns.
  <SpecCite item="org.dxos.echo.query#F-2.1" />
- If a subscriber writes from inside a notification, the write makes a separate commit, with its own notification
  after the first. <SpecCite item="org.dxos.echo.query#F-2.2" />
- A peer that was offline keeps writing to its copy. When it reconnects, peers exchange the changes each is missing and
  merge them by the rules above. Nothing is rejected for being late.
- Each change records the device that made it. This means your app can see that two devices wrote the same field and
  ask a person to confirm the result.

### History

Each object keeps its changes, and you can read them in three ways:

- `Obj.getChanges` lists an object's changes, each with the device that made it, the time, and the value before and
  after.
- `Obj.getVersion` reads the object as it was after any change, without changing the live object.
- `Filter.changes` queries changes across a space. Use it when you want to count or list them.

### Branches

A **branch** is a separate line of changes to an object and the objects it references, such as a draft of a document.
`createBranch` starts one from the latest state or from a past version.

Changes on a branch do not show on main until `mergeBranch` merges them. The merge is one CRDT merge, so main's own
changes since the branch started are kept.

- `switchBranch` shows a branch on this device, for the object and its children. Other devices keep the branch they
  are on.
- `syncBranch` brings main's newer changes into a branch.
- `deleteBranch` drops a branch.
- `db.branch` gives a second live copy of an object, bound to a branch, without switching. Use it when you want to
  show a branch next to main. Call `dispose` when the view closes.

objects that people edit in place.

## Limits

- ECHO does not know what your fields mean. When one peer sets `status: 'done'` and another sets `status: 'doing'`, one
  value wins and the other is not flagged. If the loser matters, model the intent instead. Record each person's choice
  in a field of its own, or append events to a [feed](/docs/echo/api/feed/) and derive the state from them.
- ECHO does not keep invariants across fields or objects. Two peers can each make a valid change whose merge breaks a
  rule such as "at most one task is in progress". Check such rules when you read, not only when you write.
- ECHO does not merge a schema change with data written under the old version. Use a new version and a
  [migration](/docs/echo/concepts/types/#versions-and-migrations).
- A switch to a branch is local to the device. Another device of the same person still shows main until it switches
  too.
