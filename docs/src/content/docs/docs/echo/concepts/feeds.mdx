A feed is a log that you append objects to, such as the messages of a chat. A feed can branch, so that a reader sees
one line of the conversation at a time.

## Model

In a relational database, you would keep a chat as a table of messages, and sort it by a timestamp to read it. In
ECHO, you append the messages to a feed and read them back in order.

A feed is one append log of ECHO objects, usually messages. <SpecCite item="org.dxos.echo.feeds#F-1.1" /> The feed
itself is an object in a space.

The items you append to it are objects too, with types, ids and references. However, they are not stored as objects
of the space, so a query over the space does not return them. You read them with a query whose `from` names the
feed.

`db.add` has to come first, because `db.appendToFeed` writes only to a feed that the space already stores. The two
messages go in as one batch.

A feed is a tree of branches. A **branch** is one line of items with a parent and a fixed fork point, the item of
the parent where it starts. When you read a branch, you get the items of its ancestors up to the fork point, then the
items of the branch. A branch costs about one record and needs no other object in the space.
<SpecCite item="org.dxos.echo.feeds#F-1.2" />

AI chat, comments and messaging all use this model. <SpecCite item="org.dxos.echo.feeds#F-3.1" /> These are uses of one
model, not different kinds of feed. For example, in an AI chat an agent's work on a thread runs on a branch forked from
the chat, so it stays off the reader's main branch.

## Behavior

- A **walk** reads a feed along one path of the tree: forward from the root to a branch, or backward from an item to the
  root. A walk is a query with a feed scope, so any filter works with it.
  <SpecCite item="org.dxos.echo.feeds#F-5.1" /> <SpecCite item="org.dxos.echo.feeds#F-5.2" />
- A **cursor** marks where a reader stopped, and the branch it was on. A reader resumes after the cursor and reads only
  what is new, without the items of other branches. <SpecCite item="org.dxos.echo.feeds#F-5.3" />

  To read a feed a page at a time, walk it and resume from a cursor:

  <Snippet file="concept-feeds" region="walk" />

  `Scope.feed(uri, { walk: {} })` makes the query a walk of the root branch, and `Order.natural('asc')` reads it
  oldest first. `next` is the same query with `Filter.feedCursor` added, so its 50 messages start after `cursor`.

- You rewrite an item by updating it. The update appends the whole item to the feed again under the same id. A reader
  sees the old version or the new one, and never both. <SpecCite item="org.dxos.echo.feeds#F-1.3" />

  To edit a message, update it like any other object:

  <Snippet file="concept-feeds" region="rewrite" />

  `page[0]` keeps its id and its place. A later walk returns it once, where it first stood, with the new text.

- `db.forkFeed` starts a branch at any item. A walk can also return the fork points it passes, so a reader can show
  that other branches start there. <SpecCite item="org.dxos.echo.feeds#F-5.4" />

  To start a branch, fork the feed at an item:

  <Snippet file="concept-feeds" region="fork" />

  `branch` is the id that `forkFeed` resolves with. A walk that leaves it out still reads the root branch, where
  the second message is.

- A rewind is a fork, not a separate mechanism. To go back to an earlier item, fork there and walk the new branch. The
  walk leaves out what followed that item on the old branch. <SpecCite item="org.dxos.echo.feeds#F-1.5" />

- A feed can have no index, which saves the cost of indexing a log that is only walked. Retention trims old items by
  count or age. <SpecCite item="org.dxos.echo.feeds#F-2.1" />

  You set both on the feed object:

  `indexing` and `retention` are fields of the feed object, so they replicate and merge like any other field. This
  `retention` keeps at most 1,000 items.

### When to use a feed

Use a feed for data that grows by appending and is read in order: messages, comments, events, an agent's steps. Use
objects for data that people edit in place and query by field. To try out a change to objects, such as a draft of a
document, use a [branch of objects](/docs/echo/concepts/changes/#branches), not a feed.

## Limits

The design of feeds goes further than the code does today. These parts of
[the feeds spec](https://github.com/dxos/dxos/blob/main/packages/core/echo/echo/docs/FEEDS.mdl) are not built yet:

- A list of a feed's branches and their heads, and a cheap call for the heads that changed.
  <SpecCite item="org.dxos.echo.feeds#F-2.2" />
- Sync of some branches only. A client syncs the whole feed. <SpecCite item="org.dxos.echo.feeds#F-2.3" />
- Merging a branch back, and removing a branch from reads. <SpecCite item="org.dxos.echo.feeds#F-1.4" /> A rewind
  leaves the old branch in the feed, where a walk of that branch still reads it.
- Retention per branch. Retention applies to the whole feed. <SpecCite item="org.dxos.echo.feeds#F-4.4" />
