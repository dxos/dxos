ECHO, the **E**ventually **C**onsistent **H**ierarchical **O**bject store, is a peer-to-peer graph database for
TypeScript. You use it to build apps that keep their data on the user's devices and sync it between peers.

## Model

In a client-server app, a server holds the data, and each client asks it for a copy. In ECHO, the peers hold the
data themselves:

- Peers replicate data with [CRDTs](https://en.wikipedia.org/wiki/Conflict-free_replicated_data_type). There is no
  central authority. The data lives with the clients.
- Peers sync directly with each other, and through a server when they are not online together.
- Several writers can change the same data at once, including structured objects and collaborative text.
- A peer can write while offline. Its changes merge when it rejoins the network.

Data lives in [spaces](/docs/echo/concepts/spaces/), and each unit of data is an
[object](/docs/echo/concepts/objects-relations/). [Why ECHO?](/docs/echo/why-echo/) makes the case for this design.

## Where ECHO fits in DXOS

DXOS is an open source framework for real-time, collaborative apps that keep their data on the client and sync it
peer to peer. ECHO is one of its parts:

- **ECHO** stores and replicates the data.
- **[HALO](/docs/halo/overview/)** gives each user an identity, links their devices and controls who can join a space.
- **[MESH](/docs/mesh/overview/)** is the networking that ECHO and HALO use to reach peers.
- **[EDGE](/docs/edge/overview/)** runs web services on Cloudflare Workers for sync, backup and compute.
- **[PLEX](/docs/plex/overview/)** builds apps from plugins and capabilities. [Composer](/composer), our local-first
  workspace, is built on it.
- **[TILE](/docs/tile/overview/)** is the design system, the UI components that Composer and its plugins draw with.

The SDK is under active development, and right now its features follow what Composer needs. Support for other uses is
limited, so suggestions and contributions that line up with Composer get priority. You can send feedback on
[GitHub](https://github.com/dxos/dxos/issues) or [Discord](https://dxos.org/discord).

## How these docs are organized

- **Learning path** builds one app step by step, from [The ECHO object](/docs/echo/learn/the-echo-object/) to
  [Sharing a space](/docs/echo/learn/sharing/). Start here if you are new to ECHO. On the way, you:
  1. Install `@dxos/client` and create a client.
  2. Set up an identity with [HALO](/docs/halo/overview/).
  3. Create or join a space.
  4. Add, change and query objects.
- **Core concepts** describe one idea each. Read them when you have finished the learning path.
- **Guides** cover one framework or tool each, such as [React](/docs/echo/guides/react/) and
  [Effect](/docs/echo/guides/effect/).
- **API** covers one `@dxos/echo` namespace per page, such as [Filter](/docs/echo/api/filter/). Use it to look up a
  namespace.
- **Resources** hold the generated [API reference](/docs/additional-resources/api-reference/), the
  [glossary](/docs/additional-resources/glossary/) and the [files for agents](/docs/echo/resources/llms-txt/).
