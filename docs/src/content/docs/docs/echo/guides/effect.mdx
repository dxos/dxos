By the end of this guide you will have an Effect program that asks for a database, gets one from a layer, and handles
each ECHO failure by name.

The rest of the ECHO docs use the promise API. This page is for code written with [Effect](https://effect.website/).
In Effect code, the database is a service that a program asks for, and failures are typed errors. Composer's
operations and plugins are written this way.

## Ask for the database

`Database.Service` is the database of one space. The functions of the `Database` module, such as `add`, `query`, `flush`
and `load`, are Effects that need it. This means a program that uses them says in its type that it acts on a space.

## Provide it

`Database.layer` provides the service from a database you hold.

Where a program has no database, `Database.notAvailable` stands in. It fails on use, so a missing database shows up at
the call rather than as a silent no-op.

## Handle errors

With promises, a failed call throws, and the function's type does not say what it throws. In Effect code, a failure
carries a tag, so a program handles each failure by name.

- `Database.load` fails with `EntityNotFoundError` when a reference's target is missing.
- `Blob.read` fails with `BlobNotAvailableError` when the bytes cannot be reached.

## Find a space

Some work cannot be told its space in advance, such as a trigger that fires with a fixed payload. Work like this asks
for `Hypergraph.Service`, which is every space this device holds. `Hypergraph.withDatabase` then narrows that to one
space's `Database.Service`.

If this device does not hold the space, the program fails with `SpaceNotFoundError` when the layer is built.

## Effect versions of other modules

`Feed` has Effect versions of the database's feed methods: `append`, `walk`, `query`, `fork`, `setIndexing` and
`setRetention`. `Blob` has `fromBytes`, `read`, `exists` and `url`. Each needs `Database.Service`.
