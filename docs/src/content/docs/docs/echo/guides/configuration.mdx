By the end of this guide your client will load its config from files and environment variables, and you will write
none of it in code.

`new Client()` uses built-in defaults. Pass a `Config` to choose where settings come from. Each source is a function
from `@dxos/config`, and earlier sources override later ones.

## Defaults from a file

`Defaults` returns the config in `dx.yml`. In Node it reads `config/default.yml` in your project instead.

`Local` returns the config in `dx-local.yml`. Use it when you want a development preset to sit beside the defaults. In
Node, `Local` returns nothing.

## Environment variables

`Envs` maps environment variables to config paths, as listed in `dx-env.yml`.

**Example** (Putting environment variables over both files)

<Snippet file="configuration" region="envs" />

Here, `Envs()` comes first, so an environment variable overrides both files.

Each entry in `dx-env.yml` names a variable, the config path it sets, and its type:

```yml
LOG_FILTER:
  path: runtime.client.log.filter
  type: string

DX_PERSIST:
  path: runtime.client.storage.persistence
  type: boolean
```

## Loading the files in the browser

In the browser, `Defaults`, `Local` and `Envs` read what the bundler puts in the page. To put the files there, add
`ConfigPlugin` from `@dxos/config/vite-plugin` to the `plugins` in `vite.config.ts`. It loads the three files from the
package root:

```ts
ConfigPlugin({ root: import.meta.dirname, env: ['MY_ENV_VAR'] }),
```

Vite exposes only variables prefixed with `VITE_`. To read any other variable at build time, list it in `env`. Its
value appears at the config path `runtime.app.env.MY_ENV_VAR`.

For Rollup and esbuild, `@dxos/config/rollup-plugin` and `@dxos/config/esbuild-plugin` export the same `ConfigPlugin`.

The tutorial app passes its config in code, as in [Installation](/docs/echo/learn/installation/), so it has no
`ConfigPlugin`.
