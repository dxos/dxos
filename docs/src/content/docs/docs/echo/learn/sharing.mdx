By the end of this page a second peer will have joined the app's space, and each peer will see the other's edits.

## Before you start

A space is shared by invitation. The host creates an invitation, and the guest uses it to find the host and open a secure connection. The host then gives the guest an authentication code, which the guest sends back over that connection to prove it received the invitation from the host.

Once the guest is in, both peers hold a full replica of the space's database. Each peer reads and writes its own replica, and the replicas exchange changes whenever the peers can reach each other. A peer that goes offline keeps working, and catches up when it reconnects.

[Spaces and databases](/docs/echo/concepts/spaces/#joining-a-space) explains the handshake in detail.

<Steps>

1. **Invite a peer.** `space.share` starts an invitation. Its code locates you on the network, and its authentication code proves the guest received the invitation from you.

   <Snippet file="tutorial/steps/sharing" region="invite" />

   Send the two codes over different channels. Someone who intercepts one of them cannot join.

2. **Join from the other peer.** The guest needs a client that knows the app's types and an identity of its own. It decodes the invitation, connects, and sends the authentication code back.

   <Snippet file="tutorial/steps/sharing" region="join" />

3. **Find the space.** Once authentication completes, the space is among the guest's spaces, and both peers replicate it.

   <Snippet file="tutorial/steps/sharing" region="list" />

</Steps>

## Try it

Alice created the space and Bob joined it by invitation. Edit a record on one side and watch the other follow. Switch a peer offline, edit on both sides, then switch it back on: the replicas exchange what they missed.
