By the end of this page the app will add, edit and remove records, and you will watch a record change.

## Background

An object you make with `Obj.make` exists only in memory until you add it to a database. `db.add` starts tracking it.
From then on, the database stores every change and sends it to the space's other peers.

You read a tracked object like any other, but you change it only inside `Obj.update`. The callback gets a mutable
view of the object. Each update is one change, which peers apply whole, and which notifies subscribers once.

With a REST API, a write is a request, and your code waits for the answer. In ECHO, writes are local. `db.add` and
`Obj.update` return once the change is in the local database, and replication runs after.

When two peers change the same object concurrently, both keep their edits. ECHO merges them field by field.

We put each change in the component that makes it: adding and editing in `RecordForm.tsx`, removing in
`Contacts.tsx`, and watching in `RecordGraph.tsx`.

1. **Add records.** `db.add` takes an object made with `Obj.make` and returns it, now tracked. The **New** form saves

2. **Watch a record.** `Obj.subscribe` calls back after each change to the object, and returns a function that stops
   the subscription. The graph uses it to redraw an edge when a reference moves.

   <Snippet file="echo-tutorial/app/RecordGraph" region="subscribe" lang="tsx" />

   The graph subscribes to every record. Each callback adds one to `revision`, which tells the graph to redraw.

3. **Change a record.** Every change goes inside `Obj.update`, which hands the callback a mutable view. The form calls
   this as you type.

   <Snippet file="echo-tutorial/app/RecordForm" region="update" lang="tsx" />

   Notice that `handleChange` gathers the fields that changed and assigns them all in one `Obj.update`. This means
   they reach peers and subscribers as one change.

4. **Remove a record.** `db.remove` takes the object to remove. The **×** on a row calls this.

   <Snippet file="echo-tutorial/app/Contacts" region="remove" lang="tsx" />

   <Aside type="note" title="Removed, not yet deleted">
     ECHO does not delete a removed object at once. It marks the object as removed and keeps it in the change history
     until the next [epoch](/docs/additional-resources/glossary#epoch). This means a peer that wrote while offline can
     still reconcile its changes when it reconnects.
   </Aside>

</Steps>

## Try it

Select a record and change a field. The form writes each change inside `Obj.update` as you type, and the list
follows. Press **New** to add a record of the chosen type, and press the **×** on a row to remove it. The
[React guide](/docs/echo/guides/react/) shows the form.

You can add records to a database, change them inside `Obj.update`, watch them change, and remove them.
