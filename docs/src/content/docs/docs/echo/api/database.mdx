Each space has one database. It holds the space's objects, runs queries over them and saves writes to disk.

Effect code reaches the same database as `Database.Service`. See [Effect](/docs/echo/guides/effect/) for that form.

## Add and remove objects

`db.add` stores an object or a relation. It is synchronous: it returns the object, now stored in the database, and
saves it in the background. It rejects a type, which goes through `db.addType`.

`db.remove` marks the object deleted. Queries leave it out from then on.

## Load an object

A database does not hold every object of its space in memory. To get one object, you load it:

- `db.makeRef` takes a URI and returns a reference bound to the database. Its `load` and `tryLoad` read the target
  from disk or the network. Use it when you have a URI.
- A query with `Filter.id` finds objects by id, and loads the ones this client has not loaded yet. Use it when you
  have ids.

`db.getObjectById` is deprecated. It returns an object only if the object is already in memory. For that lookup, use
`db.query(Filter.id(id)).runSync()`.

## Wait for writes

`db.flush` resolves once pending writes are on disk and in the index. Use it in a test, before the test reads back
what it wrote. Two options wait for more:

- `secondaryIndexes` waits for the full-text index too.
- `updates` waits until pending updates have reached objects and queries.

## Add types

`db.addType` persists a type and replicates it to the space's other peers. Use it for every type you store, because
`db.add` rejects a type.

If the space already holds a type with the same typename and version, `addType` returns that one and writes nothing.

`persisted` is the type the space holds. It is not always `Note`: when the space already has this typename and

## Branches

A branch is a separate line of changes to an object and the objects it references.

- `db.createBranch` starts a branch from the latest state and does not switch to it. Use it to open a draft.
- `db.listBranches` returns the names of an object's branches, with `'main'` first.
- `db.switchBranch` changes which branch this device shows, for the object and its children. Other devices keep the
  branch they are on.
- `db.mergeBranch` merges a branch into main and switches back to main. Pass `deleteAfter` to remove the branch once
  it is merged.
- `db.branch` returns a second live copy bound to a branch, without switching. Use it to show a branch next to main,
  and call `dispose` on it when you are done.

## The Hypergraph

`client.graph` is the Hypergraph, which covers every space this device holds. Use it when a query has to read more
than one space.

## Sync state

`db.getSyncState` reports how far this device is from being in sync with one other peer, across the space's
documents and feeds. That peer is EDGE unless you pass `peerId`.

`db.subscribeToSyncState` calls back as that changes. Use it when the screen shows replication progress.

## Members at a glance

| Member                                    | Summary                                                 |
| ----------------------------------------- | ------------------------------------------------------- |
| `db.add` `db.remove`                      | Store and remove objects and relations                  |
| `db.query`                                | Query the space. Returns a `QueryResult`                |
| `db.addType`                              | Persist a type so it replicates                         |
| `db.makeRef`                              | A reference bound to this database, to load its target  |
| `db.flush`                                | Wait for writes, the indexes and query updates          |
| `createBranch` `switchBranch` `mergeBranch` | Branches of objects                                |
| `syncBranch` `deleteBranch` `branch`      | Update, remove or bind a branch                         |
| `createBlob` `readBlob` `getBlobUrl`      | Store and read [blobs](/docs/echo/api/blob/)            |
| `appendToFeed` `forkFeed`                 | Write to [feeds](/docs/echo/api/feed/)                  |
| `client.graph.query` `getDatabase`        | Query every space. Find a space's database              |
| `getSyncState` `subscribeToSyncState`     | Replication progress                                    |

The full list is in the [API reference](/docs/additional-resources/api-reference/).
