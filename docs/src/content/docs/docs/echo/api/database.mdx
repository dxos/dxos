Each space has one database. It holds the space's objects, runs queries over them and saves writes to disk.

Effect code reaches the same database as `Database.Service`. See the [Effect guide](/docs/echo/guides/effect/) for
that form.

## Load an object

A database does not hold every object of its space in memory. To get one object, you load it:

- `db.makeRef` takes a URI and returns a reference bound to the database. Its `load` and `tryLoad` read the target
  from disk or the network. Use it when you have a URI.
- A query with `Filter.id` finds objects by id, and loads the ones this tab does not hold yet. Use it when you have
  ids.

`db.getObjectById` is deprecated. It returns an object only if the object is already in memory.

## Add types

`addType` persists a type and replicates it to the space's other members. Use it for every type you store, because
`db.add` rejects type entities.

If the space already holds a type with the same typename and version, `addType` returns that one and writes nothing.

## Branches

A branch is a separate line of changes to an object and the objects it references.

- `createBranch` starts a branch.
- `switchBranch` shows it on this device.
- `mergeBranch` merges it into main.
- `db.branch` returns a second live copy bound to a branch, without switching. Call `dispose` on it when you are
  done.

**Example** (Creating, switching and merging a branch)

<Snippet file="guide-database" region="branches" />

In this example, `launch` gets a `draft` branch beside `main`. `switchBranch` changes which of the two this device
shows. `mergeBranch` then merges `draft` into main, and `deleteAfter` deletes the branch.

See [Changes and branches](/docs/echo/concepts/changes/#branches) for the model.

## The Hypergraph

`client.graph` is the Hypergraph, which covers every space this device holds. Use it when a query has to read more
than one space.

The Hypergraph queries across spaces, finds a space's database by id, and holds the registry of types and objects

## Members at a glance

| Member                                    | Summary                                                 |
| ----------------------------------------- | ------------------------------------------------------- |
| `db.add` `db.remove`                      | Store and delete objects and relations                  |
| `db.query`                                | Query the space; returns a `QueryResult`                |
| `db.addType`                              | Persist a type so it replicates                         |
| `db.makeRef`                              | A reference bound to this database, to load its target  |
| `db.flush`                                | Wait for writes, indexes and query updates              |
| `createBranch` `switchBranch` `mergeBranch` | Branches of objects                                |
| `syncBranch` `deleteBranch` `branch`      | Update, drop or bind a branch                           |
| `createBlob` `readBlob` `getBlobUrl`      | Store and read [blobs](/docs/echo/api/blob/)            |
| `appendToFeed` `forkFeed`                 | Write to [feeds](/docs/echo/api/feed/)                  |
| `client.graph.query` `getDatabase`        | Query every space; find a space's database              |
| `getSyncState` `subscribeToSyncState`     | Replication progress                                    |

The full list is in the [API reference](/docs/additional-resources/api-reference/).
