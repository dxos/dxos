Each space has one database. It holds the space's objects, runs queries over them and saves writes to disk. Effect code
reaches the same database as `Database.Service`, which the [Effect guide](/docs/echo/guides/effect/) covers.

## Get a database

In plain code the database is a property of the space.

## Add and remove objects

`add` is synchronous. It returns the object, now stored in the database, and saves it in the background. `remove` marks the
object deleted; queries leave it out from then on.

<Snippet file="guide-database" region="write" />

## Run a query

`db.query` takes a filter or a query and returns a `QueryResult`. Call `run()` for the results once, or `subscribe()` to
follow them. <SpecCite item="org.dxos.echo#F-5.1" /> [Query](/docs/echo/api/query/) covers building queries.

<Snippet file="guide-database" region="query" />

## Wait for writes

`flush` resolves once pending writes are on disk. Options also wait for the indexes and for query updates, which is what a
test needs before it reads back what it wrote.

<Snippet file="guide-database" region="flush" />

## Add types

`db.add` rejects type entities. Persist a type with `addType`, which replicates it to the space's other members. If the
space already holds a type with the same typename and version, `addType` returns that one and writes nothing.

<Snippet file="guide-database" region="types" />

## Branches

A branch is a separate line of changes to an object and the objects it references. `createBranch` starts one,
`switchBranch` shows it on this device, and `mergeBranch` merges it into main. `db.branch` returns a second live copy
bound to a branch, without switching; call `dispose` on it when done. [Changes and
branches](/docs/echo/concepts/changes/#branches) explains the model.

<Snippet file="guide-database" region="branches" />

## The Hypergraph

`client.graph` is the Hypergraph: every space this device holds. It queries across spaces, finds a space's database by
id, and holds the registry of types and objects registered in code.

<Snippet file="guide-database" region="hypergraph" />

## Sync state

`getSyncState` reports how many documents this device has not yet synced with the remote peer, and
`subscribeToSyncState` calls back as that changes.

<Snippet file="guide-database" region="sync" />

## Members at a glance

| Member                                    | Summary                                                 |
| ----------------------------------------- | ------------------------------------------------------- |
| `db.add` `db.remove`                      | Store and delete objects and relations                  |
| `db.query`                                | Query the space; returns a `QueryResult`                |
| `db.addType`                              | Persist a type so it replicates                         |
| `db.makeRef`                              | A reference bound to this database                      |
| `db.flush`                                | Wait for writes, indexes and query updates              |
| `createBranch` `switchBranch` `mergeBranch` | Branches of objects                                |
| `syncBranch` `deleteBranch` `branch`      | Update, drop or bind a branch                           |
| `createBlob` `readBlob` `getBlobUrl`      | Store and read [blobs](/docs/echo/api/blob/)            |
| `appendToFeed` `forkFeed`                 | Write to [feeds](/docs/echo/api/feed/)                  |
| `client.graph.query` `getDatabase`        | Query every space; find a space's database              |
| `getSyncState` `subscribeToSyncState`     | Replication progress                                    |

The full list is in the [API reference](/docs/additional-resources/api-reference/).
