A query selects a set of entities, then can step through the graph from that set: along reference fields, backwards to
whatever references them, or across relations. Building a query does no work. It compiles to a query AST, and runs only
when you pass it to `db.query` and read the result. <SpecCite item="org.dxos.echo#F-5.2" />

## Select objects

Most queries start from a type and a few field values. `Query.select` takes any filter; these three cover most uses, and
[Filter](/docs/echo/api/filter/) has the rest.

<Snippet file="guide-query" region="common" />

## Combine queries

`Query.all` is the union of several queries. `Query.without` removes the results of one query from another.

<Snippet file="guide-query" region="combine" />

## Traverse references and relations

Each step returns a new query, so steps chain.

- `reference(field)` follows a `Ref` field to its targets.
- `referencedBy(Type, field)` goes the other way, to the objects whose field points at the selection.
- `sourceOf(Relation)` and `targetOf(Relation)` select the relations that start or end at the selection.
- `source()` and `target()` step from relations to their endpoints.

<Snippet file="guide-query" region="traverse" />

## Order results

`orderBy` takes one or more orders, applied in turn. <SpecCite item="org.dxos.echo#F-5.3" /> `Order.property` sorts by a
field; `Order.created` and `Order.updated` sort by timestamp; `Order.natural` keeps insertion order.

<Snippet file="guide-query" region="order" />

## Aggregate results

`aggregate` turns the results into records of named values: `Aggregate.count`, `sum`, `min`, `max`, `group` by a field,
`items` for the members of each group, and `created`, `updated` or `time` bucketed by a unit. It must be the last step that
selects data; only `orderBy`, `limit`, `skip` and `from` may follow it.

<Snippet file="guide-query" region="aggregate" />

## Choose sources

Without `from`, a query reads the database it runs on. `from` names the sources instead, with `Scope`: `Scope.space()` for
a space, `Scope.registry()` for the types and objects registered in code, and `Scope.feed()` for a
[feed](/docs/echo/api/feed/). `from` also takes a database, a feed object, or `'all-accessible-spaces'`.

<Snippet file="guide-query" region="scope" />

## Run once or subscribe

`db.query` returns a `QueryResult`. `run()` resolves with the results once. `subscribe` calls back each time the results
change, and `{ fire: true }` also calls it straight away with the current results. <SpecCite item="org.dxos.echo#F-5.1" />

A query reads the objects on this device first and adds what the indexes and EDGE return. A subscriber can see results
arrive in more than one step. `QueryResult.sources` lists each source with its state: pending, answered or failed.
<SpecCite item="org.dxos.echo.query#F-5" />

## Members at a glance

| Member                                  | Summary                                           |
| --------------------------------------- | ------------------------------------------------- |
| `select` `type`                         | Start a query from a filter or a type             |
| `all` `without`                         | Union and difference of queries                   |
| `.reference` `.referencedBy`            | Follow reference fields, forwards or backwards    |
| `.sourceOf` `.targetOf`                 | Relations that start or end at the selection      |
| `.source` `.target`                     | Endpoints of selected relations                   |
| `.orderBy` `.limit` `.skip`             | Order, cap and page the results                   |
| `.aggregate` `Aggregate.*`              | Count, sum, group and bucket the results          |
| `.from` `Scope.*`                       | Choose the sources                                |
| `Order.property` `created` `updated`    | Orders                                            |
| `QueryResult.run` `first` `subscribe`   | Read the results                                  |
| `QueryResult.sources`                   | Each source and its state                         |

The full list is in the [API reference](/docs/additional-resources/api-reference/).
