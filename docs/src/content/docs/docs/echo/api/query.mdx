A query selects a set of entities. From that set it can step through the graph: along reference fields, backwards to
whatever references them, or across relations.

Building a query does no work. It compiles to a query AST, and it runs only when you pass it to `db.query` and read
the result. <SpecCite item="org.dxos.echo#F-5.2" />

## Select objects

Most queries start from a type and a few field values. `Query.select` takes any filter, and `Query.type` is the short
form for a filter on a type.

## Combine queries

`Query.all` returns the union of several queries. Use it when one list shows more than one kind of thing.

`Query.without` removes the results of one query from another. Use it when you want everything except one set.

## Traverse references and relations

In a relational database, you join two tables to get from a row to the rows that point at it. In ECHO, you add a step
to the query. Each step returns a new query, so steps chain.

- `reference(field)` follows a `Ref` field to its targets.
- `referencedBy(Type, field)` goes the other way, to the objects whose field points at the selection.
- `sourceOf(Relation)` and `targetOf(Relation)` select the relations that start or end at the selection.
- `source()` and `target()` step from relations to their endpoints.

**Example** (Following references and relations)

<Snippet file="guide-query" region="traverse" />

`staff` and `workers` both reach the people at Acme. `staff` gets there through a reference field on `Person`, and
`workers` through `WorksAt` relations, which can carry fields of their own.

`orderBy` takes one or more orders and applies them in turn. <SpecCite item="org.dxos.echo#F-5.3" />

- `Order.property` sorts by a field.
- `Order.created` and `Order.updated` sort by timestamp.
- `Order.natural` keeps insertion order.

## Aggregate results

`aggregate` turns the results into records of named values. Use it when you need a number or a set of groups, and not
the objects themselves.

- `Aggregate.count`, `sum`, `min` and `max` compute one value.
- `group` groups the results by a field, and `items` gives the members of each group.
- `created`, `updated` and `time` bucket the results by a unit of time.

`aggregate` must be the last step that selects data. Only `orderBy`, `limit`, `skip` and `from` may follow it.

## Choose sources

By default, without `from`, a query reads the database it runs on. Use `from` when you want to name the sources
yourself, with `Scope`:

- `Scope.space()` reads a space.
- `Scope.registry()` reads the types and objects registered in code.
- `Scope.feed()` reads a [feed](/docs/echo/api/feed/).

`from` also takes a database, a feed object, or `'all-accessible-spaces'`.

## Run once or subscribe

`db.query` returns a `QueryResult`, which you read in one of two ways. <SpecCite item="org.dxos.echo#F-5.1" />

- `run()` resolves with the results once. Use it when you need an answer and no updates.
- `subscribe` calls back each time the results change. Use it when the screen has to stay current. With
  `{ fire: true }`, it also calls back straight away with the current results.

A query reads the objects this client has loaded first and adds what the index and EDGE return, so a subscriber can
see results arrive in more than one step. `QueryResult.sources` lists each source with its state: pending, answered or
failed. <SpecCite item="org.dxos.echo.query#F-5" />

## Members at a glance

| Member                                  | Summary                                           |
| --------------------------------------- | ------------------------------------------------- |
| `select` `type`                         | Start a query from a filter or a type             |
| `all` `without`                         | Union and difference of queries                   |
| `.reference` `.referencedBy`            | Follow reference fields, forwards or backwards    |
| `.sourceOf` `.targetOf`                 | Relations that start or end at the selection      |
| `.source` `.target`                     | Endpoints of selected relations                   |
| `.orderBy` `.limit` `.skip`             | Order, cap and page the results                   |
| `.aggregate` `Aggregate.*`              | Count, sum, group and bucket the results          |
| `.from` `Scope.*`                       | Choose the sources                                |
| `Order.property` `created` `updated`    | Orders                                            |
| `QueryResult.run` `first` `subscribe`   | Read the results                                  |
| `QueryResult.sources`                   | Each source and its state                         |

The full list is in the [API reference](/docs/echo/resources/api-reference/).
