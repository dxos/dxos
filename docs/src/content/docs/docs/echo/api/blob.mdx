A blob holds bytes, such as an image or a file. Use one to store binary data beside your objects.

In a web app, you usually put a file in object storage and keep a record of it in a database row. In ECHO, that
record is the `Blob` object. It stores the hash, size and type of the bytes and where they are.

Small blobs hold the bytes inline. An object points at a blob with a reference.

## Declare a field

To give an object a blob, declare a reference field whose target is `Blob.Blob`.

## Store a blob

`db.createBlob` hashes the bytes and uploads them to the storage backend. It returns a `Blob` object that is not yet
in the space, so you add it and then reference it.

If the bytes are over the backend's size limit, `db.createBlob` rejects with `BlobTooLargeError`.

**Example** (Storing an image and referencing it from a photo)

<Snippet file="guide-blob" region="store" />

In this example, `db.add(blob)` puts the blob in the space, and `Ref.make(blob)` points the photo's `image` field at
it.

## Read a blob

`db.readBlob` loads the bytes, from the object itself or from the backend. Use it when your code needs the bytes. It
rejects with `BlobNotAvailableError` when it cannot load them.

`db.getBlobUrl` gives a URL. Use it when you want to show the blob in a page.

In this example, `photo.image.load()` resolves the reference to the `Blob` object first. `data` then holds the bytes
as a `Uint8Array`, and `url` holds a URL for an `<img>`, if one can be made. `db.blobExists` checks whether the
bytes exist.

## Members at a glance

| Member | Summary |
| --- | --- |
| `Blob` | The blob object type |
| `db.createBlob` `db.createBlobFromUpload` | Store bytes, or adopt bytes uploaded elsewhere |
| `db.readBlob` `db.blobExists` `db.getBlobUrl` | Read bytes, check them, or get a URL |
| `MAX_INLINE_SIZE` | The largest blob stored inline |

The full list is in the [API reference](/docs/additional-resources/api-reference/).
