An annotation is a typed value attached to a schema, a field, or an object. Use one to tell a tool something about a
type that its fields do not say, such as which field labels an object.

Annotations on a type are saved with the type's schema, so they replicate with it, and a tool that has never seen
the code can still read them.

## Annotate a type

Each annotation has a `set` that pipes onto a schema, and a `get` that reads it back as an `Option`.

**Example** (Setting a label, an icon and a description)

<Snippet file="guide-annotation" region="schema" />

`LabelAnnotation.set` takes a list, so a type can name several fields that label it, in order.
`DescriptionAnnotation.set` takes the one field that describes a `Project`, and `IconAnnotation.set` takes an icon
and a hue.

This table lists the built-in annotations and what reads each one.

| Annotation | Value | What reads it |
| --- | --- | --- |
| `LabelAnnotation` | The fields that label an object, in order | `Obj.getLabel`, lists and pickers |
| `DescriptionAnnotation` | The field that describes an object | `Obj.getDescription` |
| `IconAnnotation` | An icon and a hue | Composer's navigation tree and cards |
| `FormInputAnnotation` `FormLayoutAnnotation` | Whether a field shows in a form, and the form's layout | Forms built from the schema |
| `ContentVersionAnnotation` | The fields a version field describes | [Content migrations](/docs/echo/concepts/types/#versions-and-migrations) |
| `UserType` | That the type is for people, not internal | Composer's pickers, navigation tree and collections |

## Read annotations

An annotation's `get` takes a schema and returns an `Option`. `Obj.getLabel` and `Obj.getDescription` go one step
further. They use the annotations on an object's type to read the label and the description of that object.

**Example** (Reading an icon, a label and a description)

<Snippet file="guide-annotation" region="read" />

`icon` is an `Option`, which is empty for a type that sets no icon, so `Option.getOrUndefined` unwraps it.
`Obj.getLabel` returns `'Roadmap'`, because `Project` labels its objects by `name`.

## Define an annotation

`Annotation.make` defines an annotation with an id and a schema for its value. Use it when the built-in annotations
do not hold the value you need.

You can set your annotation in two places:

- On a schema, like the built-in ones.
- On one object, with `Annotation.set`, which stores the value in the object's metadata.

`Annotation.set` writes to `roadmap`, so it runs inside `Obj.update`. `color` is an `Option`, which is empty for an
object that has no color set.

## Members at a glance

| Member | Summary |
| --- | --- |
| `make` | Define an annotation |
| `get` `set` `update` | Read and write an annotation on an object |
| `<annotation>.get` `<annotation>.set` | Read and write an annotation on a schema |

The full list is in the [API reference](/docs/additional-resources/api-reference/).
