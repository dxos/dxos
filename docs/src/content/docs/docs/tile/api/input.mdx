`Input` holds the controls of a form: text fields, checkboxes, switches and sliders, and the frame they sit in.
[Field](/docs/tile/api/field/) gives a control its label, help text and error, and [Select](/docs/tile/api/select/)
picks one value from a list.

## Parts

| Part | What it is |
| --- | --- |
| `Input.Root` | A text input |
| `Input.Textarea` | A multi-line text input |
| `Input.Number` | A number input, with steppers |
| `Input.Password` | A password input, with a button to show it |
| `Input.Pin` | A code of several single-character boxes |
| `Input.Date` | An input for a date, a time, or both |
| `Input.Checkbox` | A checkbox. `label` sets its visible label |
| `Input.Switch` | An on/off switch. `label` sets its visible label, and `indeterminate` shows a mixed state |
| `Input.Slider` | A value on a range |
| `Input.Frame` | The frame a control sits in, for building a control of your own |

`Input.Root` takes the props of an `<input>`, plus:

| Prop | Type | Effect |
| --- | --- | --- |
| `start` | `ReactNode` | Shows content before the text, such as an icon or a currency |
| `end` | `ReactNode` | Shows content after the text, such as a unit or an icon button |
| `copyable` | `boolean` | Adds a button that copies the value. It replaces `end` |
| `variant` | `'default' \| 'subdued' \| 'mono'` | Sets the look. `subdued` drops the well, and `mono` is for keys and ids |
| `noAutoFill` | `boolean` | Asks password managers not to offer to fill the input, such as for a search box |

Inside a [`Field.Root`](/docs/tile/api/field/), a control takes the field's id, label and description, so it needs no `aria-label`.
