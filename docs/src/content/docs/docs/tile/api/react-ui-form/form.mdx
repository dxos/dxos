`Form` builds a form from an Effect schema.

- Each property becomes a field of the right kind.
- The property's `title` annotation becomes the field's label.
- The schema's checks become the form's validation.

When you change the schema, the form follows.

Add the package's strings from `@dxos/react-ui-form/translations` to the `resourceExtensions` of `Theme.Provider`.

## Parts

| Part | What it is |
| --- | --- |
| `Form.Root` | The root, which takes the `schema` and the `values` or `defaultValues`. `onSave` gets the checked values |
| `Form.Viewport` | The form's container. With `scroll` it fills its parent and scrolls |
| `Form.Content` | The `form` element |
| `Form.Fields` | A field for each property of the schema, or of the properties in `include` |
| `Form.Field` | One row, bound to the form at `path` or holding controls of your own |
| `Form.FieldSet` | A labeled group of fields, which can fold |
| `Form.Layout` | The schema's fields laid out by a template |
| `Form.Actions` | The Save and Cancel buttons |
| `Form.Submit` | A submit button alone, with a label and icon of your own |
| `Form.ErrorText` | The text of a field's error |

`ObjectForm` is a `Form` over an ECHO object. It writes each change to the object as the user makes it.

## Render the form

`Form.Fields` renders a field for each property, and `Form.Actions` adds Save and Cancel.

The form checks the values as the user works:

- A field shows its error once the user leaves it.
- Save is disabled while a field the user touched has an error.
- Save checks every value against the schema, then calls `onSave` with the values.

## Edit an ECHO object

`ObjectForm` takes the type and the object. It needs no Save button, because it writes each change as the user makes
it. A property that refers to another object gets a picker of the objects of that type.

The types from ECHO's [Defining types](/docs/echo/learn/defining-types/) page work as they are.
