A composite component is a TILE component with more than one element, written as a namespace of parts. A dialog, for
example, is `Dialog.Root`, `Dialog.Trigger`, `Dialog.Content`, `Dialog.Title` and so on. You compose the parts in JSX,
in the shape you want.

## Model

If you have used Radix or Ark UI, you already know the shape. Those libraries split a component into parts that you
arrange yourself, where others give you one `Dialog` and a prop for each thing it can show. TILE does the same.

**One entry point, one namespace.** Each component is its own entry point of `@dxos/react-ui`. You import it as a
**namespace**, the object that holds its parts:

```ts
import * as Dialog from '@dxos/react-ui/Dialog';
import * as Input from '@dxos/react-ui/Input';
```

A few namespaces group related components. `Button` holds `Root`, `Group`, `Menu` and `Toggle`. `Input` holds `Root`,
`Checkbox`, `Switch`, `Textarea` and the other controls. `Layout` and `Status` each hold several small components,
which [Layout](/docs/tile/api/layout/) and [Status](/docs/tile/api/status/) list.

**Parts.** A **part** is one element of the component. `Root` holds the state, and renders either no element or the
outer one. The other parts each render one element and read the state from `Root` through React context.

A part you leave out renders nothing, so you decide what a component shows by the parts you write.

`Dialog.Root` takes no props here, so it holds the open state itself. `Dialog.Trigger` opens the dialog, and each
`Dialog.CloseTrigger` closes it.

**`asChild`.** A part with `asChild` renders no element of its own. It becomes a slot for its single child, and
passes its props, ref and handlers to that child. Use `asChild` when the child is already the element you want. In
the example above, `Dialog.Trigger asChild` makes the `Button.Root` the trigger, where the trigger would otherwise
wrap it in a second button.

**Behavior from state machines.** The parts are built on [Ark UI](https://ark-ui.com), whose components run
[zag](https://zagjs.com) state machines. The machine owns opening, closing, keyboard handling and the ARIA attributes,
and each part spreads the props the machine gives it.

## Behavior

- ARIA roles and state attributes on interactive parts come from the machine, so don't add them to such a part.
- An icon-only part still needs an accessible name, such as `aria-label` or a component's `label`.
- Layout primitives are different. `Layout.Grid` defaults to `role='none'`, so give it a role such as `list` when you
  use it with `asChild` around a list.
- A component that can be controlled takes `open` and `onOpenChange`, or `value` and `onValueChange`. If you leave them
  out, it works uncontrolled.
- Every part takes `classNames` for overrides. [Theme and tokens](/docs/tile/concepts/theme-and-tokens/) says what to
  pass in it.

## Limits

- `asChild` needs exactly one child element that forwards its ref and spreads its props. A TILE component does both.
  A plain function component that drops its props does not. In development, a part such as `Panel.Body` or
  `Layout.Flex` logs a warning for a child like that.
- A part needs its `Root` above it. Outside one it has no state to read, and it fails.
