By the end of this guide you know where TILE code goes in a plugin. You also know the four rules that keep a
plugin's UI consistent with the rest of the app.

A [PLEX](/docs/plex/overview/) plugin draws its UI with TILE. PLEX is DXOS's framework for building an app out of
plugins, and [Composer](/composer), DXOS's local-first workspace, is built with it. Composer already provides the
theme, the provider, the icon sprite and dark mode, so your plugin skips
[Installation](/docs/tile/learn/installation/) and uses the components directly.

## Components take props, and containers connect them

You may already split a React app into components that draw and components that fetch data. A plugin makes the same
split, and gives each kind a folder:

- A component, under `src/components/`, renders from its props and never reads a capability. It imports TILE and
  nothing from `@dxos/app-framework` or `@dxos/app-toolkit`, so you can show it in a story and reuse it.
- A **container**, under `src/containers/`, is the React component that a PLEX surface renders. It reads
  [capabilities](/docs/plex/concepts/capabilities/), queries the user's data and invokes
  [operations](/docs/plex/concepts/operations/), then passes the results to components as props.

A PLEX surface is a named place in the app's UI that plugins fill, which is not the surface of a TILE token.
[Surfaces](/docs/plex/concepts/surfaces/) explains how the app picks the container for a place.

## The container shape

The container owns the `Panel`. A container that fills a pane of the app or a dialog renders `Panel.Root`, with a
toolbar in `Panel.Header` and a scrolling `Panel.Body`, and puts its components in the body.
[Layout](/docs/tile/concepts/layout/) explains how the body scrolls, and [Panel](/docs/tile/api/panel/) lists the
panel's props.

Lists and forms inside the body own their spacing, so add no padding around them.

You usually build a plugin's toolbar from its actions with `@dxos/react-ui-menu`, so that other plugins can add to it.
[ActionToolbar](/docs/tile/api/react-ui-menu/action-toolbar/) shows how to build one and how to add another plugin's
actions.

## The plugin's strings

A plugin keeps its strings in a `translations.ts` resource, in a translation namespace named after the plugin's key,
and registers it in `dx.config.ts`:

```ts title="dx.config.ts"
AppCapability.translations(() => import('./src/translations.ts', { with: { type: 'module-url' } })),
```

Components read the strings with `Hooks.useTranslation`, as `ContactList` does above.
[Translations and icons](/docs/tile/concepts/translations-and-icons/) explains resources and namespaces.

## Checklist

These four rules hold for every component and container:

- Colors and sizes come from tokens and the `size` prop, never raw values.
- Overrides go through `classNames`.
- Every string a user sees comes from the plugin's translations.
- Icons are named in full, `ph--<name>--<weight>`.
