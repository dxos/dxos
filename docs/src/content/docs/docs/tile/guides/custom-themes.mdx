By the end of this guide your app has its own accent color, and a light or dark mode that follows the system or the
user's choice.

TILE's look is its tokens, the named colors and sizes that the components read. To change the look, you set new token
values in your own stylesheet. You change no component, and you write no theme function of your own.
[Theme and tokens](/docs/tile/concepts/theme-and-tokens/) explains how tokens are named and layered.

## Override tokens

The theme declares its tokens in the `theme` cascade layer. Its `dx-tokens` layer comes next, and sets the values
that change with a surface or with a density, which is how compact a region's controls are. Declare yours in
`user-tokens`, which comes after both, so yours win wherever both apply:

```css title="src/theme.css"
@layer user-tokens {
  :root {
    /* A green accent: primary buttons, links and selection. */
    --color-accent-bg: light-dark(var(--color-emerald-600), var(--color-emerald-700));
    --color-accent-bg-hover: light-dark(var(--color-emerald-700), var(--color-emerald-800));
    --color-accent-text: light-dark(var(--color-emerald-600), var(--color-emerald-400));
  }
}
```

`--color-accent-bg-hover` is a token of its own. If you override only `--color-accent-bg`, a green button turns blue
again under the pointer.

Import your stylesheet after the theme:

```tsx title="src/main.tsx"
import '@dxos-theme';
import '@dxos/react-ui/theme.css';
import './theme.css';
```

Override semantic tokens, such as `accent-*`, `fg-*` or a surface, rather than the scale. A semantic token is what the
components read. A scale value such as `--color-blue-600` is also read by everything else that happens to use blue.

Give every override a light and a dark value with `light-dark()`, in that order. A plain value applies in both modes.

The components also read `--dx-*` variables, which hold their sizes and states. `@dxos/react-ui/theme.css` sets them
in the `dx-components` layer, which comes after `user-tokens`. Override one outside any layer, where your rule wins
over every layer:

```css title="src/theme.css"
:root {
  /* A wider focus ring on every control. */
  --dx-focus-ring-width: 3px;
}
```

## Override a part of the page

Tokens are custom properties, so an override on an element applies to everything inside it:

```css
.compact-sidebar {
  --color-sidebar-surface: light-dark(var(--color-neutral-100), var(--color-neutral-950));
}
```

`--color-sidebar-surface` keeps the theme's value everywhere outside `.compact-sidebar`.

## Force light or dark

To let the user choose, keep their choice wherever your app keeps its settings, and set the class from the choice:

```ts
type Choice = 'light' | 'dark' | 'system';

const apply = (choice: Choice) => {
  const dark = choice === 'dark' || (choice === 'system' && matchMedia('(prefers-color-scheme: dark)').matches);
  document.documentElement.classList.toggle('dark', dark);
};
```

`apply` reads the media query only when the choice is `'system'`. Call it when your app starts and each time the
choice changes.

Call it from a `change` listener on the media query too. `ThemePlugin`'s script sets the class from the system again
on every change, and a listener that you add later runs after the script's.

Pass the same mode to `Theme.Provider`'s `themeMode`, so `useThemeMode` reports it to components that draw their own
canvas or chart. By default, `themeMode` is `'dark'`.

## Limits

- If you add a token, rather than override one, it yields no utility class unless Tailwind sees it in the theme. Prefer
  overriding an existing token.
- Classes that a component's stylesheet builds from a token pick up the new value at once. A color copied into your own
  CSS as a literal does not.
