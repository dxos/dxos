By the end of this page the inspector loads a plugin named Bookmarks with one module, its strings. The next four pages give it a type, a view, an action and a place in the navigation tree.

## Background

A plugin is a set of modules. Each module activates on an event and contributes capabilities, which are typed values that other parts of the app look up. [The PLEX plugin](/docs/plex/learn/the-plex-plugin/) explains how they fit. In this tutorial the whole plugin is defined in one file, `dx.config.ts`, and each module's code lives in its own file that loads only when the module activates.

## Steps

1. **Create the package.** Make a directory for the plugin with a `package.json` and a `vite.config.ts`. The package pins the `@dxos/*` packages to the version of Composer you load the plugin into, and its Vite config adds the `composerPlugin` plugin, which builds the manifest. [Publishing a plugin](/docs/plex/publishing-plugins/) lists both.

2. **Name the plugin.** The plugin's key is a reverse-domain name that no other plugin uses. Its last segment must be camelCase. Put it in a file of its own, so the manifest and any capability tags the plugin declares can both import it.

   <Snippet file="app-framework-tutorial/src/namespace" region="namespace" />

3. **Write the manifest.** `Plugin.config` takes the plugin's registry metadata and its modules. It returns the plugin's `meta` and a `make` function that the app's plugin manager calls to create it.

   <Snippet file="app-framework-tutorial/dx.config" region="config" />

   The `tags` field starts with a quality tier. A new plugin is `labs`.

4. **Add the first module.** Translations give the plugin's strings their text. The module lists the translation resource by namespace: one entry for the plugin's own strings, and one for the type the next page adds.

   <Snippet file="app-framework-tutorial/src/translations" region="translations" />

   Add it to the manifest's `modules`. `AppCapability.translations` is a module maker: it fixes the capability the module contributes and the event it activates on, so the manifest only names the file to load.

   <Snippet file="app-framework-tutorial/dx.config" region="translations" />

5. **See it in the inspector.** The **Plugin** tab shows the plugin's metadata and its one module, active. The **Translations** tab lists the strings by namespace.

   <InspectorEmbed stage="create-plugin" panel="translations" />

## Recap

You can now:

- Name a plugin with a namespace and describe it in `dx.config.ts`.
- Add a module with a module maker.
- See what a plugin contributes in the inspector.
