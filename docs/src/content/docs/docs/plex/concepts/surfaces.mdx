A surface is a named place in an app's UI that plugins fill with components. The app asks for "the article for this
object" and does not know which plugin will answer.

## Model

A person opens an object in the main area. Which component renders it, when the app was written before the plugin
that defines the object's type? With surfaces, the app names the place and passes the data, and the framework finds
the component.

Three terms describe the two sides:

- A **host** is the code that renders a surface. The app's layout is a host, and so is any component that asks for
  one.
- A **role** names a place. Each role declares the shape of the data the host passes, such as
  `{ subject, attendableId }` for an article.
- A **filter** is what a plugin contributes with its component. It names one or more roles and a guard on the data,
  for example "the article role, when the subject is a Note".

The roles a plugin fills most often come from `AppSurface` in `@dxos/app-toolkit`:

| Role | Place | What it is given |
| --- | --- | --- |
| `Article` | The main content area, one object at a time | `subject`, `attendableId` |
| `Section` | An object inside a stack or another document | `subject`, `attendableId` |
| `CardContent` | The body of an object's card, as in search results and boards | `subject` |
| `ObjectProperties` | An object's properties panel | `subject` |
| `Dialog`, `Popover` | A dialog or popover, which a plugin opens with `LayoutOperation.UpdateDialog` or `UpdatePopover` | `component`, `props` |
| `StatusIndicator` | A status indicator on the rail of Composer's complementary sidebar | No data |

[Surface](/docs/plex/guides/surface/#the-standard-roles) has the full table, and shows how to narrow a role's
`subject` to one type.

Plugins contribute surfaces through the `ReactSurface` capability.

## Behavior

- The host renders `<Surface.Surface type={role} data={data} />`. The framework collects every contribution whose filter
  names that role and whose guard accepts the data.
- Contributions are ordered by their `position`, then by plugin order. The host renders every match, or the first
  `limit` of them when it passes a `limit`.
- You can match several roles at once with `AppSurface.oneOf`, or require two conditions with `AppSurface.allOf`.
- Your component can render another plugin's surface by rendering `Surface.Surface` itself. This is how a stack shows
  each object with whatever plugin owns its type, and how a markdown document embeds a table.

## Limits

- A surface component gets only the data its role passes. It must not assume which container it is in, how wide it
  is, or that it is the only surface on screen. The same article can show in a plank, a stack or a dialog.
- The `props` mapper of a surface runs during the host's render, so it cannot call hooks. Call a hook in the component
  that the surface renders.
- A surface does not own the object it renders. Other surfaces, devices and the assistant edit the same object, so
  the component reads it reactively.
