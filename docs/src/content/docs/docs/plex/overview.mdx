PLEX is a framework for building apps out of plugins. An app is little more than the plugins it loads. Each plugin
adds types, views, actions and settings, and plugins extend each other through typed contributions instead of imports.

[Composer](/composer), a local-first workspace, is built entirely this way. Its navigation tree, deck, settings and
assistant are plugins written against the same API as yours, so a plugin from outside DXOS has the same powers as a
built-in one.

## How it works

A plugin is a set of modules. A **module** activates on an event, such as startup or the first time a view is needed,
and then contributes to capabilities. A **capability** is a typed slot that modules contribute values to and other
modules read. A React component for a surface, a handler for an operation and nodes for the navigation tree are all
values a module contributes.

No module imports another plugin. One plugin can therefore render inside another plugin's view, or add an action to
another plugin's objects, without either knowing about the other.

The pieces live in `@dxos/app-framework`. `@dxos/app-toolkit` adds what a workspace app needs: App Graph, layout,
settings and the standard surface roles. [Plugins and modules](/docs/plex/concepts/plugins/) explains how the pieces
fit.

A plugin also gets three things for free:

- Its data is [ECHO](/docs/echo/overview/) objects in spaces. The data syncs between a person's devices and the people
  they share with, merges concurrent edits, and works offline, without the plugin doing anything for it.
- Its operations and skills are tools that Composer's assistant can use as soon as the plugin is installed.
- Its views use the same [TILE](/docs/tile/overview/) components as every other plugin, so plugins written by
  different people look like one app.
