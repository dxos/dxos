A plugin never writes its UI text inline. It contributes translation resources, keyed by language and namespace, and
reads strings by key, so the app can show them in the person's language and other plugins can label its objects.

## Contribute translation resources

A resource maps a language to namespaces, and each namespace to keys and their text. Use the plugin's key as the
namespace for its own strings, and a type's typename for the strings that describe the type.
`AppCapability.translations` contributes the resources; it activates at startup, since labels are needed for the
first screen.

## The keys the app reads for a type

The app labels objects of a type from that type's namespace, so a type with these keys reads well in every menu:

| Key | Where it shows |
| --- | --- |
| `typename.label` | The type's name, such as in the create menu. |
| `typename.label_zero`, `_one`, `_other` | The plural forms, such as a section heading. |
| `object-name.placeholder` | The name of a new object before the person names it. |
| `add-object.label` | The create menu's entry for the type. |

## Read a string from a component

`useTranslation` takes a namespace and returns `t`. A key with a `count` picks its plural form.

translates it where it renders.
