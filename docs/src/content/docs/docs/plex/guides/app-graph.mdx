App Graph is a graph of everything a person can open or do in a PLEX app. In Composer, the navigation tree,
toolbars, context menus and the command palette all read it. This means a plugin that adds to App Graph shows up in
all of them.

App Graph comes from the App Toolkit, not the framework. It is how a workspace app such as Composer organizes what
plugins add, and a PLEX app can run without it.

## How App Graph is shaped

A **node** has an id, a type, data and properties. Its data is usually the thing it stands for, such as a space or an
ECHO object. Its properties carry the label, icon and display hints. The graph starts from a root node.

Nodes connect by **relations**:

- `child` makes the navigation tree. A space's children are its sections and objects.
- `action` connects a node to the things a person can do to it. An action node's data is a function that returns an
  Effect.
- Other relations, such as `companion`, attach panels to a node.

A node's identity is its **path**, which is the ids from the root down to it, joined like a URL. `GraphPath` from
`@dxos/app-toolkit` builds the paths of the common nodes, such as a space or an object in it. Navigation operations
take paths, and in Composer the address bar shows the open node's path.

Plugins add nodes through **builder extensions**. An extension has a matcher and a connector. The matcher picks the
nodes it applies to, and the connector returns the nodes to connect to them.

## How it behaves

- App Graph expands lazily. The framework runs a node's extensions only when something asks for that node's
  connections, such as the person opening a branch in the tree. A space with ten thousand objects costs nothing until
  it is opened.
- A connector reads reactive state through `get`. When that state changes, such as a query gaining a result, the
  connector reruns and the node's connections update.
- Nodes that nothing is showing can be dropped again. If your plugin must keep a node loaded while it is off screen,
  such as the one a panel is pinned to, contribute it through `AppCapabilities.AppGraphRetention`.
- Actions reach every menu from one place. An action node carries a disposition that says where it appears: `toolbar`
  for an object's toolbar, `list-item` for its context menu in the tree. The command palette lists every action of the
  open node, so an action needs no command of its own.

## Write a graph builder extension

`AppGraphBuilder.createExtension` takes an id, a matcher and a connector.

- The matcher returns `Option.some(value)` for the nodes it applies to. `AppNodeMatcher` has ready-made ones such as
  `whenSpace`.
- The connector returns the nodes to connect. Read reactive state with `get` so the connector reruns when it changes.

## Attach actions to nodes

`AppGraphBuilder.createTypeExtension` matches nodes whose data is an object of one type. Its `actions` callback returns
action nodes.

- `AppGraphNode.makeAction` makes an action node, and `disposition` decides where it shows.
- `AppNode.makeToolbarAction` is a shortcut for the object toolbar.

## Work with AppNode and GraphPath

`AppNode` builds the common kinds of node:

- `makeObject` makes a node for an ECHO object.
- `makeSection` makes a heading in the tree.
- `makeCompanion` and `makeDeckCompanion` make panels.

`GraphPath` builds and parses node paths, which navigation operations take.

`useAppGraph` returns the graph builder, and its `graph` field is the graph. Expand a node before you read its

changes.

## Limits

- An extension's id and a node's id must be camelCase. A hyphenated id is dropped without an error.
- A connector must be cheap and must not write. It runs again on every change to the state it reads.
- Paths are stable only while the ids along them are. Moving an object to another space changes its path.

## Members at a glance

| Member | Summary |
| --- | --- |
| `AppGraphBuilder.createExtension` | Add nodes or actions to the nodes a matcher picks |
| `AppGraphBuilder.createTypeExtension` | Add nodes or actions to the nodes of one object type |
| `TypeSection.createTypeSectionExtension` | List a type's objects under a section in each space |
| `AppNodeMatcher.whenSpace` `whenNavTreeGroup` | Match a space, or a group in its navigation tree |
| `AppGraphNode.make` `makeAction` `makeActionGroup` | Make a node, an action or a group of actions |
| `AppNode.makeObject` `makeSection` `makeGroup` | Make the node of an object, a section or a group |
| `AppNode.makeCompanion` `makeDeckCompanion` | Make the node of a panel |
| `AppNode.makeToolbarAction` | Make an action for an object's toolbar |
| `GraphPath.getSpacePath` `getObjectPath` | Build node paths |
| `AppGraph.expand` `getConnections` `getActions` | Build and read a node's connections |
| `graph.connections` | A node's connections, as an atom |

The full list is in the [API reference](/docs/plex/resources/api-reference/).
