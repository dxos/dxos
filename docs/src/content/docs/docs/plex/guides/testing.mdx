This guide tests a plugin's modules without an app. By the end, you have a test that starts your plugin, fires
activation events, reads capabilities and invokes an operation.

A plugin's modules run in a plugin manager, so a test starts one. `Harness.createComposerTestApp` starts a headless
app with the core plugins Composer gives every plugin, plus the plugins under test. It needs no browser, account or
server.

The headless app has no client and no spaces of its own. To test code that reads a space, add the client plugin,
`ClientPlugin` from `@dxos/plugin-client`, to `plugins`.

## Invoke an operation

`harness.invoke` runs an operation through the app's invoker, with the handlers the plugins contributed, and returns
its output. A typed error fails the promise. Use it for an operation that needs no space.

An operation that reads a space needs three more things: the client plugin, an identity, and the id of the space to
run in. `harness.invoke` passes no space, so run `Operation.invoke` through the harness's `runPromise` and give it
the `spaceId`.

## Limits

- The harness renders no UI. Test a surface's component on its own, with a story or a component test.
- Plugins that need a real network or device, such as a connector, need their own test layers.
