The framework defines how plugins extend each other, but not what an app is made of. `@dxos/app-toolkit` adds that
for a workspace app such as Composer: a layout, App Graph, settings, translations and the standard surface roles.

Its capabilities are in `AppCapabilities`, and Composer and any other app built with the toolkit read them.

`AppCapability` has a module maker for most of them. A module maker is a function that makes a module for one
capability. It sets the activation event and the environments, so `dx.config.ts` names only the file.

## A tour, by group

Most plugins touch a handful of these. The rest exist for the plugins that build the app's own features. If your
plugin is not one of those, you can ignore them.

- For layout, `Layout` is the current layout as an [atom](/docs/plex/resources/glossary/#atom), a reactive value that
  code subscribes to. It holds what is open, the sidebar and the mode. Plugins read it, and the layout plugin provides
  it. To change it, use `LayoutOperation`.
- For App Graph, `AppGraphBuilder` adds nodes and actions, `AppGraph` is the graph itself for reading, and
  `AppGraphRetention` keeps nodes loaded while they are off screen. [App Graph](/docs/plex/guides/app-graph/) covers
  them.
- For settings and text, `Settings` adds a section to the settings page, and `Translations` gives the plugin's
  strings their text. [Settings and state](/docs/plex/guides/settings-and-state/) covers settings, and
  [Translations](#translations) below covers text.
- For schema, `Schema` registers the ECHO types the app can create, name and list. The
  [ECHO](/docs/plex/guides/using-echo/) guide covers it.
- For the assistant, `SkillDefinition` gives it a skill, `Toolkit` adds tools outside a skill, and `McpServer` exposes
  a built-in MCP server.
- For files and content, `FileUploader` stores an uploaded file, and `Exporter` adds Print and Save to a type's
  objects. `TextContent` extracts an object's text for search and the assistant. `PluginAsset` publishes a file
  other tools can read, such as the plugin's spec.

## Translations

A plugin never writes its UI text inline. It contributes translation resources, keyed by language and namespace, and
reads strings by key. The app can then show them in the person's language, and other plugins can label its objects.

### Contribute translation resources

A resource maps a language to namespaces, and each namespace to keys and their text. Use the plugin's key as the
namespace for its own strings, and a type's typename for the strings that describe the type.

`AppCapability.translations` contributes the resources. It sets no activation event, so the module waits for `Idle`,
like any module with no `activatesOn`. It activates sooner if a module that requires `Translations` activates first.

### The keys the app reads for a type

The app labels objects of a type from that type's namespace, so a type with these keys reads well in every menu:

| Key | Where it shows |
| --- | --- |
| `typename.label` | The type's name, such as in the create menu. |
| `typename.label_zero`, `_one`, `_other` | The plural forms, such as a section heading. |
| `object-name.placeholder` | The name of a new object before the person names it. |
| `add-object.label` | The create menu's entry for the type. |

## Surface roles

The roles a plugin fills most often are in `AppSurface` from `@dxos/app-toolkit`:

| Role | Where it renders | What it is given |
| --- | --- | --- |
| `Article` | The main content area, one object at a time | `subject`, `attendableId` |
| `Section` | An object inside a stack or another document | `subject`, `attendableId` |
| `CardContent` | The body of an object's card, as in search results and boards | `subject` |
| `ObjectProperties` | An object's properties panel | `subject` |
| `Dialog`, `Popover` | A dialog or popover, which a plugin opens with `LayoutOperation.UpdateDialog` or `UpdatePopover` | `component`, `props` |
| `Navigation` | The navigation sidebar | `current`, the active workspace's id |
| `StatusIndicator` | A status indicator on the rail of Composer's complementary sidebar | No data |

[Surface](/docs/plex/guides/surface/#the-standard-roles) has the full table. A plugin can render into any role
another plugin defines, and declare its own. See [Surfaces](/docs/plex/concepts/surfaces/).

## App capability or a new one

- Use an app capability when you are adding to something the app already shows, such as a setting, a node or a
  skill.
- Declare a new capability when other plugins add to something your plugin shows. The Space plugin does this when it
  declares `SpaceCapabilities.CreateObjectEntry` for the types in its create menu.

[Capability](/docs/plex/guides/capability/) shows how.
