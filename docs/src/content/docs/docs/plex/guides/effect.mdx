A module's body and an operation's handler are Effects. This means you can read the capability manager as an Effect
service, contribute layers of your own, and name the services an operation needs.

## Read capabilities as a service

Inside a module, the capability manager is `Capability.Service`. `Capability.get`, `getAll` and `waitFor` read it
for you. Yield the service itself when you need the manager.

## Contribute a layer

A service that an operation uses comes from a layer. To supply one, contribute a `LayerSpec` to
`Capabilities.LayerSpec`. The spec says what the layer provides, what it requires and how widely one instance is
shared.

With `affinity: 'application'`, the app builds the layer once and every operation shares it.

## Declare an operation's services

An operation lists the services it needs in `services`. When you invoke it, the runtime builds them from the layer
specs that plugins contributed. The handler yields them like any Effect service.

If an operation's services have no layer, the operation fails when it is invoked, not when the plugin loads.
[Testing a plugin](/docs/plex/guides/testing/) catches it.

## Limits

- Never run an Effect with `Effect.runPromise` inside a module. Return it, so the plugin manager can interrupt it
  when the module deactivates.
- A layer spec's service is in-process. A service that must run on EDGE needs a layer there too.
