`Operation` defines operations, attaches their handlers and invokes them. An operation is a named action with a typed
input and output, and [Operations](/docs/plex/concepts/operations/) explains why the UI and the assistant share them.

## Define an operation with input and output schema

`Operation.make` defines an operation. It takes metadata and two schemas, one for the input and one for the output.
The key in the metadata is a DXN, the DXOS name for a resource.

`Operation.mutation` classifies the operation's effect on state:

- `'none'` changes nothing.
- `'write'` changes data in a way that can be undone.
- `'destructive'` deletes, or cannot be undone.

Use it so that a tool can tell a person what the operation does before it runs.

## Implement handlers and group them

`Operation.withHandler` attaches an Effect to a definition. The Effect takes the input and returns the output.

`SlugifyHandler` is checked against the two schemas of `Slugify`. A handler that returned a field other than `slug`
would not compile.

A handler set groups handlers, and you make one in two ways:

- `OperationHandlerSet.make` groups handlers that are already loaded.
- `OperationHandlerSet.lazy` takes handlers made with `Operation.lazyHandler`, whose modules load the first time each
  operation runs.

Contribute the set through `Capabilities.OperationHandler`.

## Invoke an operation and handle its typed errors

`Operation.invoke` takes a definition and an input, and returns an Effect. The Effect needs the operation service,
which the framework provides to modules, handlers and graph actions. It fails with `NoHandlerError` when no plugin
handles the operation.

**Example** (Invoking an operation and catching a typed error)

<Snippet file="app-framework-guide-operation" region="invoke" />

`Effect.catchTag` takes `NoHandlerError` out of the type of `slugOf`, so its callers have no error left to handle.
When no plugin handles `Slugify`, they get the title back unchanged.

From React, use `useOperation` or `useOperationInvoker`. See [React](/docs/plex/guides/react/).

## The built-in layout operations

`LayoutOperation` from `@dxos/app-toolkit` changes what is on screen.

- `Open` opens items by their node paths, and `Close` closes them.
- `Set` replaces the open items.
- `ScrollIntoView` scrolls an item into view.
- `UpdateSidebar` and `UpdateDialog` open, close or change the sidebar and the dialog.
- `AddToast` shows a toast notification.

## Members at a glance

| Member | Summary |
| --- | --- |
| `make` | Define an operation from a key, metadata and two schemas |
| `withHandler` `lazyHandler` | Attach a handler, loaded now or on first use |
| `invoke` `schedule` | Run an operation and wait for its output, or queue it as a follow-up |
| `mutation` `idempotent` `visible` | Annotate an operation's effect |
| `Service` | The operation service that `invoke` needs |
| `NoHandlerError` | The error when no plugin handles an operation |
| `OperationHandlerSet.make` `lazy` `merge` | Group handlers, loaded or lazy, and combine sets |
| `LayoutOperation.Open` `Close` `Set` | Change which items are open |

The full list is in the [API reference](/docs/plex/resources/api-reference/).
