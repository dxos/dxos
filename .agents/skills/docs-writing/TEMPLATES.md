# The voice by template

The spec's `template` blocks fix each page's parts. This table says how the voice in [`SKILL.md`](SKILL.md) sits in
them.

Go by the page's shape where the spec's template name does not fit. A page with `<Steps>` follows the `tutorial`
row, whatever its group. A guide without steps follows the Guides row. A TILE component page follows the `reference`
row.

| Template or page      | How the voice applies                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `home`                | The docs home is one short paragraph on DXOS as a whole, and a grid. The spec fixes the paragraph's content. Bring it to the house style and no further.                                                                                                                                                                                                                                                                     |
| `overview`            | Open with what the section is, in one paragraph. Give the section in brief, then where it fits with the rest of DXOS and where to go next. This page gives the section its foothold, and it introduces the DXOS names it uses, such as Composer and EDGE. The guarantees belong to the concept pages.                                                                                                                        |
| `narrative`           | A Why page. It owns the section's contrast with the usual way, which the overview gives one sentence. Each problem section starts from the problem and names the mechanism that removes it. Show the problem in code where the section has an API a reader calls. "We" is fine.                                                                                                                                              |
| `tutorial`, opener    | The first page of a learning path, such as The ECHO object. It says what the path builds and shows the finished thing. It has no steps. It introduces the terms the path leans on.                                                                                                                                                                                                                                           |
| `tutorial`, step page | Say "we". Open with what the app gains on this page. In Background, give the facts the steps rely on, each tied to the step that uses it. In Steps, each bold lead is an instruction. The sentence after a step's sample is for the line a reader would get wrong, and a step with no such line ends on its sample.                                                                                                          |
| `concept`             | Open with the definition, then what the reader uses it for. Model holds the page's foothold and its samples, under H3s when it has more topics than four leads carry. Behavior and Limits hold one claim to a bullet. A claim that a spec item states carries its citation. Say what the reader sees, or on a machinery page what the system does.                                                                           |
| `namespace`           | Open with what the namespace is for. Under each task heading: what, when, the sample, what not. A concept page may show the same sample. Then explain it here for the call, and there for the idea.                                                                                                                                                                                                                          |
| `reference`           | A TILE component page. It opens with the live preview or story, then the import line, then one sentence that says what the component is, with its common noun as subject where it has one: "An accordion is a stack of sections." The sample, if any, follows that sentence. A part with its own heading gets what it is and when to use it. A part that sits only in the Parts table gets no sentence that repeats its row. |
| Guides                | Open with what the reader will have at the end, or with the definition when the guide is about one thing. Then the pattern of a namespace page.                                                                                                                                                                                                                                                                              |
| Glossary              | An entry is a full sentence with the term as its subject, "A swarm is the set of …", then any further facts, each in its own sentence. Its heading links to the page that explains the term, and the entry needs no "See" sentence. The glossary holds every term the section's pages put in bold.                                                                                                                           |
| Other resources       | Configuration, samples, llms.txt and API reference pages. Open with one sentence on what the page lists. The rest gets rule 4 and the house style.                                                                                                                                                                                                                                                                           |
