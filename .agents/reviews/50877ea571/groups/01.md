# WARN `.agents/skills/agentic-review/lib/store.mjs:99`

The bare `catch { return []; }` in `ruleIdsFromReviewDir` swallows any failure reading/parsing `groups.json` (corrupt JSON, permissions error, race after the `existsSync` check) and silently falls back to "no rules seen," which makes `prepare.mjs` treat every rule as new and full-scan — masking a real problem rather than tolerating a known, named condition. Per the harness-script-hygiene rule, either narrow the catch to the specific tolerated failure (mirroring the `ENOENT` handling in `readReview` just above) with a comment explaining why swallowing it is safe, or log/rethrow unexpected errors instead of defaulting to `[]` unconditionally.
