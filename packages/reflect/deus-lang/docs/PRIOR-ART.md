## What was left out, and why

- **A dependent type theory.** Lean's kernel is the gold standard for proofs, but the first goal is
  a self-hosting toolchain. The proof ladder starts with checks that are honest about their
  strength (closed evaluation, exhaustive enumeration, property tests) and records which one
  ran ([D13](./DECISIONS.md)).
- **Unison's shallow handlers.** See [D7](./DECISIONS.md).
- **Effect-TS's runtime services (`Layer`, `Scope`, fibers).** These are library concerns in
  DEUS: a `Layer` is a handler, and a scope is a handler that runs finalizers on `return`.
- **Unison's random `unique` type GUIDs.** Types are nominal by IRI instead ([D6](./DECISIONS.md)),
  which gives a type a stable, human-meaningful identity across versions.
