# Explorer usability probe: baseline (2026-10-16)

Dmytro's idea: a small model explores the hosted explorer with no prompting about the site, and its
report shows how well it understood and how direct its path was. This is the run before the guided
structure of D196. Model: Haiku. Tool: `node scripts/visit.mjs <url> [--click <text>]…`, 25 visits at
most. Site: https://deus.dmytro-a80.workers.dev/@dxos/toolchain/ (deploy f8d82204).

## What it understood

A code browser for `@dxos/toolchain`, the compiler and toolchain of a functional language, DEUS
(algebraic types, pattern matching, effects). The site never says so; it inferred it from the Tour
namespace and the task board.

## The path (topic: the parser), 15 visits

- Spec: **not reached.** `Parser`'s comment cites `Syntax.Spec R-3`, but there is no link; Syntax → Spec
  opened the top-level `Spec` namespace (12 definitions) instead of `Syntax.Spec` (27).
- API: found (`Parser.*`, 113 definitions). Tests: found by name under `Tests`, not linked from the
  list. A definition's source: found (`Parser.over`).
- The most useful entry point was the `Tour` namespace, found by chance on visit 12.

## Where it was lost

1. No start-here or README: nothing says what DEUS is or what the site is for.
2. The kind glyphs (T, A, ƒ, ✓, ∀, S, ◇, ◎) have no legend.
3. `Spec` names two different things; a sub-namespace's count disagrees with the card it opens.
4. Requirement ids cited in comments (`Syntax.Spec R-3`) are not links.
5. "Not checked yet" and "Used by: nothing yet" do not say whether a test runs or passes.
6. Hash URLs (`#d:fd6a58…`) and a page title that is always the site make bookmarks hard to use.
7. The TS view leaks DEUS-only syntax (`#[List<Text>, List<Text>]`).
