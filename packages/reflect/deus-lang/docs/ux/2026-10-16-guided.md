# Explorer usability probe: after the guided explorer (2026-10-16)

The same probe as [the baseline](./2026-10-16-baseline.md), with the same prompt, after D196 (deploy
958f8a31). Model: Haiku. 13 visits.

## What it understood

Correctly, from the front page alone: DEUS is a language whose definitions are stored by content hash,
this is its toolchain (compiler, back ends, explorer), and it compiles itself. The sidebar is grouped
by area ("The language and its kernel", "The codebase", "Back ends", …).

## The path (topic: Array)

- Spec: **found** (Array.Spec: API block, laws L-1 to L-10, requirements R-1 and R-2, with the tests
  that prove them).
- API: found, both in the spec's API block and in the Array namespace.
- Tests: found (`Array.Spec.versionsIndependent`).
- A definition's source: found (`Array.set`, a primitive; `Tour.total` for DEUS source).

## Where it was lost, and what was done

1. The spec said "2 of 2 requirements proved" while the test said "Not checked yet". The header now
   says requirements "name their tests", unrun evidence says "no result yet", and a test without a
   result says why (results are kept where `deus test` ran).
2. A definition did not link back to its spec. Definitions now show "Specified in" their namespace's
   spec document.
3. Clicks changed the address but the text showed the old page: `scripts/visit.mjs` read the page before
   the card was drawn. It now waits for every card the address names.
4. The front page uses terms a newcomer does not know (D96, Perceus, R2, prim). Not addressed yet.
5. Tasks do not link to the definitions they concern in the page text. Not addressed yet.
