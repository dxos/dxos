# Decision log

The agent's log of choices between real alternatives, newest last. The user's own
words live in [`USER.md`](./USER.md) and win over anything here.

| # | Decision | Alternatives | Why |
| --- | --- | --- | --- |
| D1 | New package `@dxos/deus-lang` at `packages/reflect/deus-lang`, next to `@dxos/deus`. | Grow `@dxos/deus`. | `@dxos/deus` is the `.mdl` CodeMirror extension, consumed by `plugin-code`; a language runtime is a different dependency footprint. The language is still called DEUS and reads `.mdl` documents. |
| D2 | Self-hosting by a **seed**: a TypeScript *kernel* that only evaluates Core IR, plus a checked-in Core image of the compiler (`seed/deus.seed`). Every front-end stage (lexer, parser, resolver, hasher, codebase, CLI, test runner, prover, wasm backend) is DEUS source under `deus/`. | Keep a TypeScript front-end permanently. | The first goal is that the compiler, CLI and codebase are written in DEUS. OCaml, Rust and Unison all bootstrap from a stored previous build; the kernel is the only TypeScript left. |
| D3 | A throwaway TypeScript front-end (`src/stage0`) produces the first seed only, and is deleted once the seed reproduces itself. It refers to definitions by name, not by hash. | Make stage0 hash-identical to the DEUS front-end. | Bootstrapping only needs a semantically correct first compiler. The real check is the fixpoint `seed₁ = seed₂`, which does not involve stage0. |
| D4 | Core IR is a small, canonical S-expression language. It is the hashing input, the on-disk object format, and the kernel's load format. | JSON; binary. | One canonical text form keeps the TypeScript kernel and the DEUS printer byte-identical with very little code, and parses in a few dozen lines of DEUS. |
| D5 | Definitions are named by SHA-256 of their canonical Core, with dependencies replaced by their hashes and locals as de Bruijn indices; mutually recursive groups are hashed as one cycle (Unison's scheme). | Hash source text. | Names become metadata, renames are free, and test/proof results can be cached by hash. |
| D6 | Types and abilities are nominal by IRI. A declaration without an explicit `@"iri"` gets `urn:deus:<fully.qualified.Name>`. The hash also covers the constructor shapes, so one IRI can have several versions. | Unison's random `unique` GUIDs; purely structural types. | The user asked for IRIs. An IRI names a type's lineage across versions, which is what migrations need. |
| D7 | Algebraic effects are **deep** handlers with multi-shot continuations (Koka/Eff semantics), written Unison-style: `\| op args -> k => body`. | Unison's shallow handlers. | Deep handlers make the common handlers (state, exceptions, generators) one clause each; shallow handlers need a named recursive function every time. |
| D8 | The kernel is a CEK machine with an explicit frame stack, so a captured continuation is a copied stack segment. | Compile to JS closures in CPS. | Multi-shot resume needs re-entrant continuations; an explicit stack also removes JS stack-depth limits on deep recursion, and counts steps for performance requirements. |
| D9 | `Int` is a 32-bit wrapping integer on every backend. | JS doubles; BigInt; i64. | The interpreter and the wasm backend must agree bit for bit, so differential testing between them can be exact. i32 maps directly to wasm and to `x \| 0` in JS. |
| D10 | Equality (`==`, `=`) and ordering (`<`, `compare`) are structural primitives, not type classes, for now. | Lean `BEq`/`Ord` instances. | There is no type checker in the first milestone; structural equality is what theorems compare anyway. |
| D11 | Layout follows a Lean-like offside rule: a body that starts on a new line is a block whose statements share a column; a token at the start of a line at or left of the block's column ends the current expression. | Braces and semicolons. | The user asked for Lean syntax. Sequencing in direct style (no monads, effects in the arrow) needs `let x := e` lines, not `do` notation. |
| D12 | `deus/` holds the compiler as `.deus` text files for review in git; the content-addressed codebase in `.deus/` is derived from them by `deus add`. | Check the codebase store into git. | Reviewers read diffs of text. The store is reproducible from the text because hashing is deterministic. |
| D13 | Proof evidence has levels: `sorry` < `tested n` (property-based, n generated cases) < `proved` (`rfl` by closed evaluation, `decide` by exhaustive enumeration of finite binders). Results are cached by the theorem's hash. | Implement a full dependent type theory first. | An honest ladder (Velvet/Cedar) gives value now; each level says exactly what was checked. Induction and rewriting are the next rung. |
| D14 | Three failure tiers. **Errors** are the ordinary ability `Throw e` in the effect row, discharged by handlers. **Defects** (failed match, division by zero, `defect "…"`) are requests on the built-in `#Defect` ability raised by the kernel: a handler at a boundary (test runner, REPL) may observe them, but never resumes them; unhandled, the run exits 70. **Panics** are kernel invariant failures (a JS exception inside the kernel); DEUS code cannot catch them, exit 71. | One exception type for everything (JS); Effect-TS `Cause` trees. | User request ("errors (checked, expected), defects (code is bugged), panics (kernel broken)"). Making defects an ability reuses the handler machinery, so no second unwinding mechanism exists. |
| D15 | A mutable `Ref` cell primitive (`Ref.new/get/set`), not rolled back by multi-shot resumption. The parser and the codebase loader use it for their cursor and caches. | Thread state explicitly through every parser function; a `State` handler. | A `State` handler costs a stack-segment copy per request; explicit threading doubles the parser's size. Unison has `Ref` too. When the type checker lands, `Ref` operations will carry an effect so purity stays visible in signatures. |
| D16 | `Option` is open in every file, so `none`/`some` resolve to its constructors. A bare identifier pattern is a constructor only when it resolves *exactly* (namespace chain or `open`), never by suffix; otherwise it binds a variable. | Lean resolves bare constructor patterns with the scrutinee's type; treating every identifier that suffix-matches a constructor as one. | No types in the first milestone. Suffix matching would make common variable names (`value`, `text`) silently become constructors. |
