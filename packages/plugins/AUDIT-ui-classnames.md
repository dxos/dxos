# UI className audit — Composer plugins

Scope: `packages/plugins/*/src/{containers,components}/**/*.tsx` (stories excluded) in the 65 plugins that carried a
flex/grid wrapper, an `h-full`, or a raw palette colour. Every change is meant to be behaviour-preserving
except the rows marked visible below. Result: 185 fixes in 133 files across 55 plugins; 28 of them change
what renders (theme-token swaps, one display fix, two dead classes made live).

Rules applied:

- **Wrapper divs → `Layout.Flex` / `Layout.Grid`** only as a straight swap of an existing element. Gaps map to the
  ramp exactly (`gap-1`→`xs`, `gap-2`→`sm`, `gap-3`→`md`, `gap-4`→`lg`, `gap-6`→`xl`, `gap-8`→`2xl`); other gaps
  stay as classes. `1fr` tracks become `'fill'` (`minmax(0, 1fr)`). No wrapper was added.
- **Redundant classes removed** where the primitive's recipe already sets them (`h-full` under `Panel.Body`, `dx-fill`
  / `min-w-0` / `dx-grow` on `Panel.Root` / `Panel.Body`, `flex items-center` on `SearchList.Item`, `grid
overflow-hidden` on `MobileLayout.Root`). A full-height child under `Panel.Body` became `Panel.Body asChild` (the
  child made `Util.composable` where needed: ibkr `ReportSections`).
- **Raw palette colours → theme tokens** (`text-<hue>-text`, `bg-<hue>-bg` for solid fills, `text-success|warning|error-text`,
  `text-fg-muted|subtle`, `border-separator`). Palette colours that are data (chart series, instrument and LED
  colours, drawing palettes, game pieces) were left.

Verification: each plugin typechecked against sources (no new errors vs a pre-edit baseline) and its storybook suite
run (`moon run <plugin>:test-storybook`). See the PR for results.

Merged from the `### Gaps` tables of all 65 plugin reports. Paths are relative to `packages/plugins/<plugin>`; where a report named only a file, the bare file name is used. A file can appear under more than one pattern. Patterns are ordered by how many files hit them.

### Primitive limitations found

Each of these was checked against `packages/ui/react-ui/src/layout/Grid/Grid.tsx`, `layout/Flex/Flex.tsx`, `util/slots.ts`, `packages/ui/ui-types/src/slot.ts` and `packages/ui/ui-theme/src/css/utilities.css`.

- **(a) Layout.Flex/Grid reject event handlers.** Both are built with `slottable()`, so consumers see `SlottableProps<P>`. That is `ThemedClassName<P>` plus `Pick<HTMLAttributes, 'children' | 'role' | 'style'>` plus `asChild`. JSX still lets `data-*`/`aria-*` through, but `onClick`, `onKeyDown`, `onFocusCapture`, drag/paste handlers, `tabIndex`, `title`, `inert` and spread prop bags (`getRootProps()`, landmark/focus props) fail to type-check. This blocked conversions in lingo, markdown, sequencer, inbox, tasks, file, deck and chess.
- **(b) Grid `cols`/`rows` are inline styles.** `trackList()` writes `style.gridTemplateColumns/Rows`, and an inline style beats any `@3xl:grid-cols-[…]` or `sm:grid-cols-3` class. Responsive and container-query templates therefore cannot use the props (inbox, trip, chess, sidekick).
- **(c) `cols='subgrid'` always adds `col-span-full`, and `rows='subgrid'` always adds `row-span-full`.** No subgrid can span only part of its parent (space CollectionSection and SchemaContainer). `Card.Row` already has a `span` prop, but Grid does not.
- **(d) Grid defaults to `role='none'`** (`role={role ?? 'none'}`), while Flex sets no default role. Converting a focusable landmark, an ActionMenu trigger child or a `role=table` host changes its semantics (deck ComplementarySidebar, navtree L0Menu, atproto AtprotoCompanion).
- **(e) Files that export their own `Layout` (or `Panel`) clash with the namespace import** `import * as Layout from '@dxos/react-ui/Layout'`. The affected files are plugin-presenter `src/components/Presenter/Layout.tsx` and `src/components/Markdown/Panel.tsx`, and plugin-testing `src/components/Layout/Layout.tsx`. The repo has no precedent for aliasing the import, so these files were left unconverted.
- **(f) Grid's JSDoc is wrong about clipping.** The `grow` prop doc says "Fill and clip the parent (`dx-expand`)", and the render comment says "`dx-expand` already clips". In fact `dx-expand` = `dx-grow dx-fill` = `flex-1 min-h-0 min-w-0 h-full w-full`, with no overflow rule. Flex `grow`, by contrast, is `flex-1 overflow-hidden`. So the two `grow` props differ: Grid's fills without clipping, and Flex's clips without filling.
- **(g) Flex `grow` is not `dx-grow`.** `flex-1 overflow-hidden` neither sets `min-h-0/min-w-0` explicitly nor matches a bare `grow` (flex-grow only). Auditors kept `dx-grow` and `grow` classes rather than swap them (atproto PdsBrowser, calls Lobby/ResponsiveGrid).
- **(h) `mx` (tailwind-merge) resolves display conflicts.** Passing `hidden @4xl:flex` or `hidden lg:grid` through Layout.Flex/Grid, or a class string that holds both `flex-col` and `flex-row`, can drop a class. So responsive show/hide cannot be a straight swap (chess ChessArticle, deck ComplementarySidebar, onboarding Welcome).
- **(i) The `gap` ramp has no per-axis variant and no step below `xs`.** `gap-x-3 gap-y-1`, `gap-y-3`, `gap-x-2` and `gap-0.5` stay as classes (routine, iroh-beacon, commerce, atproto).
- **(j) `Panel.Body asChild` needs exactly one composable child.** Conditional siblings (empty vs content), several children, or a non-composable child (`Masonry.Root`, `NavigationStack`) block the swap, so `flex flex-col`/`grid` stays on the Body and `h-full` stays on `Status.Empty` (chess-com, github, space, library, lingo, markdown, commerce, studio, mobile, video).
- **(k) Composable roots cannot be slotted onto Layout.** A root that spreads `Util.composableProps(props, { classNames: 'dx-expand flex flex-col' })` would need its className merge re-plumbed (assistant Chat, file Preview).
- **(l) `Card.Text`/`Typography` `lines` is not a pure clamp.** It also applies the first-line-centring metrics (padding and alignment), so swapping `line-clamp-n` for `lines={n}` changes rendering (magazine, blogger).
