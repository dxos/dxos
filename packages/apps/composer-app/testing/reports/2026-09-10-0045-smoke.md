## Findings

- **`after` 2 passes, and the fix was exercised rather than bypassed.** This is the point of the run.
  The teardown failed exactly as it did in run 2 — the server log carries
  `DataSpaceManager#0 space teardown failed; deleting anyway … "message":"Edge connection closed."`
  from `EdgeClient._closeCurrentConnection` — and the deletion completed anyway: the invoke returned
  in 4.6 s instead of rejecting, and the space is gone from both the snapshot and the live client
  list. Run 2 hit the same `Edge connection closed.` and was left with a stranded `SPACE_CLOSED`
  space. Same failure, opposite outcome, which is what the fix claims.
- **`$stepErrors` behaved as intended, though this run could not stress it.** Nothing was logged at
  ERROR level during the window, so `$stepErrors` and `$snapshot.errors` agree at zero. The binding's
  value shows against run 1, where one background error at step 1 falsified the cumulative clause for
  every later step; here there was nothing to diverge.
- **The snapshot's error channel is narrower than the page console, and that is worth knowing.**
  `composer.snapshot({ since: 0 })` reported zero errors for the whole session while the server log
  shows `console.error` lines inside the run window — `SwarmNetworkManager#0 Error: Edge connection
  closed.` at 00:45:46, among others. The buffer is not broken: dispatching a synthetic `ErrorEvent`
  was captured immediately as `uncaught error`, so recording is live and `collectErrors` works. The
  gap is upstream — those subsystems report to the console without going through `log.error`, so they
  never enter the buffer the snapshot reads. Consistent across all three runs: no
  `SwarmNetworkManager` entry has ever appeared in a snapshot's `errors`. This is why the runbook
  requires reading the server log and the `[page]` lines once per test, and it means a green
  `$stepErrors` is not by itself proof that nothing went wrong. Not fixed; recorded.
  (The one `uncaught error` entry now in the buffer is that probe, dispatched after `after` 3 — it
  postdates every verdict above.)
- **The proxy flags hold:** `ERR_CONNECTION_RESET` 0, against 55 in run 1. The boot still shows the
  shared-worker leader session timing out once before re-election, same as both earlier runs.
- QA-1 `status:` set to `passing` with the date.
