---
title: Nodes, groups and edges
description: The .dx language - boxes, frames around them, and the arrows between them.
---

A `.dx` file has four kinds of statement: `diagram`, `node`, `group` and `edge`. Each takes one line, except a
group, which wraps its members in braces. A `#` starts a comment that runs to the end of the line.

**Example** (Describing a web app with two groups)

```dx
diagram flow=down                     # optional
group web "Web app" {
  node Browser "Browser"
  node Api "API server"
}
group data "Storage" {
  node Db "Postgres"
  node Cache "Redis"
}
node Queue "Queue"
node Worker "Job worker"
edge Browser -> Api "HTTPS"
edge Api -> Db "reads, writes"
edge Api -> Cache
edge Api -> Queue "enqueue"
edge Queue -> Worker
edge Worker -> Db
```

`Queue` and `Worker` sit outside both groups, so they get no frame.

## diagram

`diagram` sets options for the whole picture. It is optional, and first when present:

```dx
diagram flow=right aspect=16:9
```

`flow` is the direction most arrows run: `down` (the default), `up`, `right` or `left`. `aspect` asks for a picture
of that shape, such as `16:9` for a slide.

## node

`node <id> ["label"] [placement…] [ref="path"] [shape=…]` draws one box:

```dx
node Api "API server" shape=rect ref="services/api/src/server.ts"
```

- The id is a bare word of letters, digits, `_` and `-`. Edges refer to it.
- The label defaults to the id. It is drawn on one line in a fixed-width box, so keep it to about 17 characters.
  The id can be as long as you like.
- `shape` is `rect` (the default), `ellipse`, `diamond` or `triangle`.
- `ref` names the file the box stands for, so the diagram can be checked against the code.
- Placement words, such as `below Api`, are [layout hints](/docs/language/hints/).

Declare every box with `node` before an edge uses it. An edge to an undeclared id is an error.

## group

`group <id> ["label"] [placement] [compact] [max-width=N] { … }` draws a dashed frame around its members:

```dx
group data "Storage" {
  node Db "Postgres"
  node Cache "Redis"
}
```

A node is in a group only if its `node` line is inside that group's braces. Each id and each group is declared
once. To move a box into a group, move its `node` line inside the braces. Edges refer to ids, so they stay where
they are.

Groups do not nest, and each needs at least one member. Three or fewer keep a diagram readable.

## edge

`edge <from> -> <to> ["label"]` draws an arrow:

```dx
edge Browser -> Api "HTTPS"
edge Api <-> Cache
edge Api -- Logger
edge Api -> Db, Cache
```

- `->` has one arrowhead, `<->` two and `--` none.
- `edge A -> B, C` draws one arrow from A to each of B and C.
- Label only the edges that say something, in a few words.

In place of the arrow, a word such as `extends` or `depends-on` says what the edge means and picks the arrowhead.
[Relations](/docs/language/relations/) lists the words.

## Reserved words

`diagram`, `group`, `node`, `edge`, `cell`, `via`, `bus` and `compact` are reserved. Quote one to use it as an id:
`node "bus" "Event bus"`.
