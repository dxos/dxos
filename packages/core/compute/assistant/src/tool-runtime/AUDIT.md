# Tool-name audit

Every `Operation.make` definition in the repo with a `meta.key` (DXN) and `meta.name`, and the
tool name the model calls — derived in `makeToolName` ([services.ts](./services.ts)) by
lowercasing `meta.name` and mapping every non-alphanumeric to `-`. The DXN key is NOT used for the
model-facing name, so renaming display copy renames the tool (and invalidates every memoized
conversation fixture that recorded it).

Generated by a source scan (regex over `Operation.make` meta blocks); regenerate by re-running the
scan after adding or renaming operations. **Wired** marks operations referenced by a
`Skill.toolDefinitions({ operations: [...] })` — the model-facing set; unmarked rows are
app/runtime operations that only become tools if a skill binds them.

## Summary

- 116 named operations across 20 packages; 62 wired into skills; 5 operations have a key but no `meta.name` (never bindable as tools as-is).
- **Duplicate tool names among skill-wired operations: `create`, `open`, `update`** — two skills bound into one session would collide.
- Duplicate tool names across all operations: `create`, `fibonacci`, `forex-effect`, `open`, `query`, `reply`, `sleep`, `update`.
