# Scout survey: RDF + SPARQL inside one Cloudflare Durable Object

Scope: approaches other than the four already being benchmarked (Comunica over a SQLite RDF/JS source,
SPARQL→SQL compiler, Oxigraph in memory + SQLite journal, Oxigraph `spareval` over DO SQLite). They are
listed in the table for reference only and are not ranked.

All measured numbers here come from the deployed worker
`https://rdf-bench-comunica-pushdown.dxos.workers.dev`. The DO SQLite probes ran on version
`3afe9c88-0559-4e08-8d7a-c65192d663d5` through `GET /sqlprobe?db=sqlprobe-1|2`; the in-memory store
probes ran on version `46dd5f97-7fa1-426d-a61e-86c03774082e` through `GET /memprobe`. Probe source is in
`variants/comunica-pushdown/src/{sql-probe,mem-probe}.ts`. Results for the variant I built are in
[comunica-pushdown](comunica-pushdown.md).

## 1. Ranked candidates

The two hard constraints are the 128 MB isolate (JS heap and wasm share it) and DO SQLite as the only
durable store that is in-process and synchronous. Two things therefore decide the ranking: whether the
data has to live in memory, and how much of each query runs inside SQLite rather than in JS.

**Recommendation.** Keep SQLite as the system of record and make the engine push as much as possible
into it. #1 does this today with no new dependencies; its main remaining cost is Comunica's own
per-query floor (about 2–3 ms) and the filters it still evaluates itself (typed `xsd:decimal` and dateTime comparisons: Q3 146 ms and Q4 75 ms at 1M triples). A typed numeric column in SQL would remove those; #2 might lower the floor once it matures.
Add #3 (FTS5) for text predicates whatever engine wins, and treat #5 (sharding) as the answer past the
10 GB / about 10M-triple scale rather than as a v1 concern.

Implications for every SQL-backed variant:

- FTS5 trigram is the in-SQL substitute for `CONTAINS` and `REGEX`.
- `WITH RECURSIVE` can evaluate `+` and `*` property paths inside SQLite.
- `ANALYZE` / `PRAGMA optimize` are available, so the planner gets real statistics for self-joins.
- The 100-parameter cap shapes bulk insert (multi-row `VALUES` of at most 25 quads).
- No UDFs means any SPARQL function SQLite lacks (REGEX, typed comparisons on lexical forms) must be
  pre-computed into columns or evaluated in JS.

## 3. Harness notes

- **The oracle canonicalises `xsd:dateTime`.** Oxigraph returns `…00.68Z` for an input of `…00.680Z`, and
  `checksumRows` normalises numerics but not dateTimes. Every engine that preserves lexical forms gets a
  wrong checksum on Q2, Q3 and Q4 from 10k facts up, with correct row counts. `comunica-pushdown`
  canonicalises at ingest to match.
- **`agg_group_concat` probe.** Oxigraph leaves `?ps` unbound because `GROUP_CONCAT` over IRIs is a type
  error under the spec. Comunica concatenates the IRI strings instead. Every Comunica-based variant
  fails this probe, and the cause is engine leniency, not storage.
- **Deploy propagation.** For up to about a minute after `wrangler deploy`, new DO instances can still
  start on the previous version; one of my runs got old code. Probe a fresh `db` (for example
  `/stats`) before starting a run.
